# X Nook v1.3.33

发布日期：2026-11-17

本版聚焦「授权」这一条线：把散落在系统设置各处的权限收进一个页面，并把「更新后授权失效」这个根因修掉。

## 权限中心

设置里新增独立的「权限」页，列出应用实际需要的六项授权：

| 项目 | 用途 | 系统分页 |
| --- | --- | --- |
| 屏幕与系统音频录制 | 实时字幕订阅系统音频（只订阅音频，不录画面） | 屏幕与系统音频录制 |
| 语音识别 | 把音频在本机转成文字 | 语音识别 |
| 日历 | 读取日程并在灵动岛提醒 | 日历 |
| 自动化 · Apple Music | 发送播放/暂停/切歌指令 | 自动化 |
| 自动化 · Spotify | 同上 | 自动化 |
| 开机启动 | 登录后在后台启动 | 登录项 |

每项都给出状态徽标、用途说明与操作：

- **请求授权**：主动调用系统接口触发弹窗，同时把应用登记进对应列表。此前应用从不主动请求屏幕录制，用户只能在系统设置里自己找应用；现在点一下就出现系统对话框。
- **打开系统设置**：深链到具体分页，不是笼统的「隐私与安全性」。
- **重置记录**：`tccutil reset <服务> com.meteorkid.xnook`，用于「开关是打开的但应用仍报未授权」。
- **拖拽添加**：权限页顶部提供可拖拽的应用图标，按住拖到系统设置列表里即可完成添加，不需要先去 Finder 找应用。

状态判断也做了区分：屏幕录制授权后当前进程仍需重启才能捕获，界面显示「已授权 · 需重启」并给出「立即重启」，不再一律报「未授权」。实时字幕的状态行改为读取同一份结论，两处显示不会互相矛盾。

## 签名与授权继承

上一版把「授权重置」归因于 Hardened Runtime，这个判断不完整。真正的原因在代码签名的 designated requirement：

```text
# ad-hoc
designated => cdhash H"3496b847ed5d3eb57b07601803388b0488f9c997"

# 固定证书
designated => identifier "com.meteorkid.xnook" and certificate leaf = H"07d5ba22…"
```

ad-hoc 签名没有证书，requirement 只能锚在 cdhash 上。每构建一次 cdhash 就变一次，macOS 校验 TCC 记录时匹配不上，于是把新二进制当成另一个应用——但系统设置里的开关还保留着，看起来是打开的。这就是「明明授权了却显示未授权」和「一更新就要重新授权」的共同来源，Hardened Runtime 只是改变了 cdhash 的取值。

本版起构建使用一个固定的本地自签名身份：

```bash
./scripts/setup-signing-identity.sh   # 一次性创建，私钥存在独立钥匙串
./build-app.sh                        # 之后自动使用该身份
```

身份存放在 `~/Library/Keychains/xnook-signing.keychain-db`，口令在 `~/.xnook-signing/password`（600）。构建时临时把该钥匙串加入搜索列表，签名后立即还原，不长期改动用户的钥匙串配置。`XNOOK_SIGN_ADHOC=1` 可强制退回 ad-hoc。

代价是这次身份变更本身会让现有授权失效，**升级后需要最后一次重新授权**；此后跨版本继承。

## 媒体

补齐 v1.3.31 起在本地验证、但未进入发布包的播放中心桥接：ad-hoc 签名的进程调用 `MRMediaRemoteGetNowPlayingInfo` 只能拿到空字典，改由 Apple 平台签名的 `/usr/bin/perl` 加载 C 桥接（BSD 3-Clause，`ejbills/mediaremote-adapter`）读取与发送指令。哔哩哔哩、QQ 音乐、网易云音乐等发布 Now Playing 的应用现在能读出曲目并接受控制。

## 验证与安装包

- 安装包：`XNook-1.3.33.dmg`，Apple Silicon（arm64），macOS 14 或更高版本。
- 签名：本地自签名证书 + Hardened Runtime（`flags=0x10000(runtime)`），未使用 Developer ID，未公证。首次打开如被 Gatekeeper 拦截，请右键「打开」。
- 桥接实测：安装包内 `perl run.pl libCMediaRemote.dylib get` 返回 `com.bilibili.bilibiliPC` /「【Adele】历年演唱会全场合集」/ `isPlaying=true`。
- 签名实测：`codesign -d -r-` 输出证书锚定的 requirement，重新完整构建后该值不变（同一证书叶哈希），`codesign --verify --strict` 通过。
- 发布前全量测试：XNook **1311 项，101 项条件跳过，1 项环境性失败**（`GifResourceTests` 的书签用例需要带 `com.apple.security.files.bookmarks.app-scope` 的签名宿主，SwiftPM 沙箱不提供该 entitlement），授权核心与发码核心全部通过。该失败与本次改动无关，可用 `scripts/test-signed-bookmarks.sh --filter GifResourceTests` 验证。
