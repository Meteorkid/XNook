## 一、结论先行：上一版方案不是最好的

**本文不是最优方案。** 补做检索后确认四处可改进：

1. **音源层漏项**：对非 DRM 网页视频，直接抽取 HLS/DASH 分片或独立音轨，在音质（无损、不混系统通知音）、可预取性（可提前拉取未来分片，天然满足"识别进度超前"）、权限（无需屏幕录制授权）三方面都优于系统音频回环。正确做法是四级降级：媒体流抽取 → 浏览器 tabCapture → 系统回环 → 虚拟声卡。
2. **模型层架构性疏漏**：本文把「非流式模型 Whisper + 滑动窗口重译」当作流式主选，属于绕路。原生流式架构（RNN-T / Conformer / Paraformer / Zipformer）首字延迟 70–140 ms，比批处理 Whisper 的 1,200–3,200 ms 低一个数量级。合理分工是原生流式模型负责快轨，Whisper large-v3 负责预转写与精修。
3. **策略层选型偏保守**：§5.2 写「AlignAtt 需替换推理栈，暂不采用」是**判断错误**。AlignAtt 是零训练的推理时策略，成本在于读取模型内部交叉注意力权重，不是重训。相对 wait-k 与 LocalAgreement，它平均高约 2 BLEU 且延迟低 0.5–0.8 秒（Interspeech 2023）。应列为首选，LA-2 作为无注意力权重时的降级。
4. **修订协议不够严谨**：§七的字符数/时间启发式阈值，可升级为「模型内部对齐覆盖率 + KV 缓存快照回退」，并引入专有名词豁免替换机制。

**还需收回第一轮的一处表述**：`accuracy = f(lookahead)` 仍不完整。训练侧手段（FastEmit、SelfAlign、ConstAlign）可在不增加前瞻的前提下降低预测延迟，更准确的刻画是 `accuracy = f(lookahead, alignment_policy, context_bias)`。

**公开专利文献提示的重复风险**：本文 §5.2 的快慢双引擎构思，与一组 2020-12-15 优先权、已在美国（US 11,532,312 B2、US 11,929,076 B2）与欧洲（EP 4 264 602 B1，2025-08-20 授权，Active）获授权、另有中国同族（CN 116635932 A）公开的专利文献高度重合。该组文献明确描述了「主引擎高准确率长前瞻 + 副引擎低延迟短前瞻并行 → 副结果先入 word list → 主结果合并替换」。其独立权利要求含特征级拼接限定，与本文的文本层合并不完全相同，但欧洲授权文本权利要求全文未取得，无法判断覆盖范围。若本功能对外分发，建议在实施前委托专业机构做一次正式检索并出具意见。此处仅为事实记录，不构成任何法律结论。

## 四、三处最实质的技术补正

**① 音源层：媒体流分片抽取**

对非 DRM 网页视频，直接抽取 HLS/DASH 分片或独立音轨相比系统回环有三项优势：无损（平台原始编码，不混系统通知音、不做 48→16 kHz 重采样）、可预取（按时间窗提前拉取未来分片，天然满足「识别进度超前」）、免屏幕录制权限。开源项目「流声字幕」已实现三级降级：媒体抽取 → Chrome tabCapture → 系统声音捕获，并处理了拖动进度条重对齐、AudioWorklet 重采样、窗口重叠去重等细节。

反向证据：Chrome Live Caption 只监听经 Mojo 注册的 `AudioOutputDelegate` 输出流，B 站用 flv.js + WebAssembly + Web Audio API 混音会绕过该路径。说明「系统级捕获」通用但粗放，「音源级抽取」精确但需按站点适配——应并存且按可用性降级。

**② 模型层：原生流式 vs 离线模型包装**

| 方案 | 首字延迟 | 技术词汇 WER | 资源 |
|---|---|---|---|
| Sherpa-ONNX / Zipformer (RNN-T)，原生流式 | 70–140 ms | 11.8–15.5% | 1.2–2.0 GB |
| FunASR / Paraformer（非自回归），原生流式 | 百毫秒级 | 中文 CER 3.8% | 轻量 |
| Whisper large-v3（批处理） | 1,200–3,200 ms | 7.2–9.8% | 4.5–9.5 GB |
| 云端流式（低延迟档） | 180–320 ms | 6.5–8.9% | 客户端 <40 MB |

RTF 对比（5 分钟音频）：FunASR 流式 0.06（约 16 倍实时）> Paraformer-large 0.15 > Qwen3-ASR-1.7B 0.23 > Whisper-large-v3 0.31。

结论：上一版把"精度最高的模型"硬包装成流式是绕远路。正确分工是原生流式模型负责快轨，Whisper large-v3 负责预转写与精修。

**③ 策略层：AlignAtt 优于 LocalAgreement**

AlignAtt（Interspeech 2023）用 decoder 交叉注意力定位候选词对应音频帧，若落在缓冲区末尾「不可访问帧」窗口内则判语境不足、继续等待。相对 wait-k 与 LA：平均高约 2 BLEU，LAAL 延迟降低 0.5–0.8 秒，零训练零适配，单一参数 f 调节延迟/质量。局限是注意力弥散会导致决策不稳定。开源项目 SimulStreaming 已实现该策略并获 IWSLT 2025 同传冠军。

## 五、从公开专利文献学到的三个改进

1. **类别词保护**：精修回填时，专有名词类词元应豁免替换。补上原设计修订协议的漏洞——高精度引擎在专有名词上未必更准。
2. **单模型双分支共享 encoder**：比跑两个独立模型省算力。对 M3 Max 意义有限，对内存受限设备关键。
3. **对齐覆盖率 + KV 快照回退**：把修订决策从外部启发式阈值提升到模型内部对齐信号 + 状态回滚。

## 八、需要收回的两处表述

1. 「实时与准确在物理上互斥」（第一轮回答）：不精确。更完整的刻画是 `accuracy = f(lookahead, alignment_policy, context_bias)`——训练侧手段（FastEmit / SelfAlign）可在不增加前瞻的前提下降低预测延迟。
2. 「AlignAtt 需替换推理栈，暂不采用」（§5.2）：判断错误。它是零训练的推理时策略，成本在于读取交叉注意力权重，不是重训。

## 九、「最好」这个提法本身的问题

本节给出的是「2026-11 可检索公开信息下的方法空间更优位置」，不是绝对最优：

- 无单一最优解：音源可预取性、语言、是否联网、是否允许音频出本机、延迟预算——不同约束下最优解不同。
- benchmark 不可横比：各来源测试集、归一化规则、硬件都不同（LibriSpeech 朗读语音 vs AMI 远场会议，WER 可差 5 倍）。数字用于判断量级，不用于精确排序。
- 专利状态会变：部分 2026 年公开的申请仍在审查，权利要求可能被修改或驳回。
