## 二、本案客体适格性论证模板（技术问题 → 技术手段 → 技术效果）

### 2.0 判断路径

按整体考虑原则分三步：① 权项整体是否含技术特征——含则**不落入** A25.1(2) 智力活动规则；② 是否构成 A2.2 技术方案——须同时具备利用自然规律的**技术问题、技术手段、技术效果**；③ 含算法/规则特征的权项再按 **6.1.2** 检验：与计算机系统内部结构是否有特定技术关联、是否解决提升硬件运算效率或执行效果的问题、是否获得符合自然规律的内部性能改进效果。仅主题名称出现「智能 / AI / 系统级」等字样不足以克服客体缺陷，关键看**主题名称之外的限定内容**。

### 2.1 技术问题

**推荐表述（示例，供代理师改写）**：

> 在应用无关、音源身份可动态变化的本地计算环境中，多个字幕证据来源的产出时刻、估计耗时、可预取性与是否允许异步各不相同，且部分结果会在首帧呈现后才到达；如何在有限的本地推理单元、内存与音频缓冲预算内，使多条候选字幕轨按统一时间坐标持续覆盖播放进度，**把首帧输出延迟的上界约束为与来源数量无关的可配置常量**，同时避免对不可预取音源保留无效的长前瞻音频缓冲、避免音源跳变与晚到证据引发的重复转写与对已呈现条目的回改。

**危险 / 禁止表述（易被认定为智力活动规则或主观问题）**：

| 写法 | 问题 |
| --- | --- |
| 「如何根据用户偏好智能选择字幕来源」 | 人为设定的主观规则，不含技术问题 |
| 「如何让字幕更准确、更懂用户」「提高字幕准确率」 | 效果导向、主观，且检索已证明「更准的单点」全部在先公开 |
| 「如何智能地编排 / 融合多来源字幕证据」 | 「智能」「编排」「融合」为抽象规则，未落到技术数据 |
| 「按版权等级 / 订阅等级 / 用户等级选择来源」 | 商业 / 管理规则（指南第二部分第一章第 4 节列举类型） |
| 「如何提高字幕质量、提升观看体验」并作为唯一技术问题 | 主观体验，不当然构成技术问题；6.1.3 仅在由技术特征或相互作用的算法特征共同带来时才考虑 |

### 2.2 技术手段

**必须落到具有确切技术含义的数据与动作**（对应指南 6.3.1「输入参数 / 输出结果与具体技术领域数据相对应」）：音频数据、音频帧、音频指纹、音源描述符、播放时钟、播放前沿、绝对源时间戳、音频缓冲区、推理单元负载 U、峰值内存、代次标识、状态机（易变 / 已稳定 / 已读 / 已修正）。

| 本案要点 | 应写成的可操作技术特征 | 技术性落点 |
| --- | --- | --- |

### 5.3 组合发明在创造性评价中的常见质疑

1. **已知手段的简单并列**：审查员可能认为各特征分别解决各自问题（Myna 管提前缓存、`US8775174B2` 管补缺口、`US12641305` 管关键路径、`CN122334404B` 管收敛），彼此只是并列叠加，无功能上相互作用关系。
2. **缺乏技术启示 / 组合动机**：若各单点均为本领域常规手段，易被认定「本领域技术人员容易想到」；反之，若现有技术存在**相反教导**（如「等所有轨到齐再仲裁」、`US12641305` 把字幕移出关键路径），可用来论证无组合动机。
3. **效果可预期、无协同**：被认定组合后的效果等于各单点效果之和，不存在「突出的实质性特点和显著的进步」。
4. **三步法中技术问题被上位化**：区别特征实际解决的技术问题若被重述为「如何更好地显示字幕」这类宽泛问题，容易得出显而易见结论；须把技术问题锚定在 2.1 的系统内部量上。
5. **事后诸葛亮（hindsight）**：答复时应指出「只有已知本申请方案后才会把可预取性、首帧时限、收敛写入规则捆绑」，避免以本申请为蓝图拼装对比文件。
6. **算法特征贡献被忽略**：若答复未论证算法特征与技术特征功能上彼此支持、存在相互作用关系，审查员可能不计入算法特征的贡献（6.1.3）。

### 5.4 应对写法（供代理师改写）

- **技术启示**：论证现有技术各自面向不同边界与相反目标——Myna 面向「本地文件＋自带播放器」且明确排除系统音频监听；`CN116635932B` 是同一音频流上双引擎恒定并行；`US8775174B2` 是「字幕空白补缺」而非「关键路径时延上界」；`CN202511057472` 按语义重要性评分分配；`US20120290298A1` 按高显著性分配算力。现有组合没有动机把「可预取性」作为**跨音源决定证据链长度**的一等控制量，并把「到点即渲染＋晚到证据只写未读后续区间」作为不回改已呈现条目的硬约束。
- **协同效果**：论证各要件功能上相互支持——剪枝决定证据链长度与缓冲占用，首帧时限决定关键路径上界，收敛写入规则决定晚到证据能否安全接入而不回改已呈现条目，绝对源时间戳索引是多轨仲裁与指纹重锚的共同基准，可预取度 P 是剪枝与时限的共同输入。其中「**输出延迟上界与来源数量无关**」正是「剪枝（链长可变）＋时限（到点即渲染）＋收敛写入（不等晚到来源）」共同作用的结果，任一单独特征均不能获得；按 6.1.3，该相互作用关系使算法特征对技术方案的贡献应在创造性审查中予以考虑。
- **意想不到的技术效果**：按常理「来源越多、汇聚越慢」，本案通过到点即渲染与晚到证据仅写后续区间，反而使关键路径不随来源数 N 增长，把延迟上界约束为可配置常量 `L_budget`；同时重复转写次数、峰值内存与音频缓冲数据量下降、推理单元利用率上升。主张时应表述为「组合后产生非各单点效果之和的系统内部性能改进」，并避免写成商业 / 体验收益。
