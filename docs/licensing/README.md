# XNook 授权与售卖方案

本文档说明如何生成邀请码、把软件卖出去、以及这套机制的**能力边界在哪里**。

---

## 一、整体设计

```
   你（持私钥）                   用户（持公钥验证）
        │                                │
        ├─ licensegen 发码 ──┐           │
        │                    ├─ 邀请码 ──┤
        └─ 管理后台发码 ─────┘           │
                                         ▼
                               App 本地验签 → 放行 / 拒绝
                                         │
                                         ▼
                              首次激活时上报一次（可选）
                                         │
                                         ▼
                                    管理后台台账
```

**核心原则：放行决策完全在本地。** 服务器只做记录，不参与放行。

这样设计的原因：如果放行依赖服务器，那么服务器宕机、你忘记续费、域名过期、用户断网，任何一种情况都会让**已付费的用户无法使用软件**。对一个个人维护的软件，这是最昂贵的客服成本。当前设计下，服务器彻底消失也不影响任何已激活用户。

## 二、邀请码结构

```
XNK1-0400-0001-06FF-GF8X-MSE2-...-RV87
└┬─┘ └──┬───┘ └────────┬─────────┘
 │      │              │
 │      │              └─ 64 字节 Ed25519 签名（Base32 编码）
 │      └─ 6 字节载荷：版本(1) + 序列号(4) + 标志位(1)
 └─ 品牌前缀
```

- 总长 **116 字符**（含前缀），28 组每组 4 字符
- 字符集为 Crockford Base32，**排除了 I / L / O / U**，避免手抄混淆
- 解码时容错：`I`/`L` 视为 `1`，`O` 视为 `0`，大小写不敏感

### 为什么码这么长

因为本项目是 **source-available（源码可见）**。验证逻辑对所有人公开，所以：

- **不能用对称密钥**（HMAC / 共享密钥）——任何人读源码就能自己造码
- **只能用非对称签名**——你持私钥，App 只嵌公钥
- Ed25519 签名固定 **64 字节**，这是码长度的主要来源，无法压缩

**接受这个现实**：短码 + 离线验证 + 源码公开，三者不可能同时成立。所以码长，但可以复制粘贴，也可以点击 `xnook://activate?code=...` 一键激活。

### 标志位

| 位 | 名称 | 用途 |
|---|---|---|
| 1 | `perpetual` | 永久授权（当前唯一授权类型） |
| 2 | `earlySupporter` | 早期支持者，日后可据此发放额外权益 |
| 4 | `complimentary` | 人工赠码，与销售码区分以便统计 |

## 三、首次配置（只做一次）

### 1. 生成密钥对

```bash
cd /Users/meteor/github/XNook
swift run licensegen keygen --out Sources/XNook/Licensing/LicensePublicKey.swift
```

输出示例：

```
私钥：license-private.key  (权限 600，请离线保管)
公钥（Base64）：
  DirNvRGU9cKbEnHCN2E+4Y+7SM9Fx8w/+Cp0oyvEBqI=
✓ 已写入公钥源码：Sources/XNook/Licensing/LicensePublicKey.swift
```

### 2. 立即把私钥移出项目目录

```bash
mkdir -p ~/.xnook-license
mv license-private.key ~/.xnook-license/
chmod 600 ~/.xnook-license/license-private.key
```

**这一步不能省。** 私钥等同于印钞机——持有它的人可以签发任意数量的有效邀请码。一旦提交进 Git 历史，即使后续删除，历史里仍然存在，必须视为已泄露并重新生成密钥对。

同时确认 `.gitignore` 已忽略：

```
*.key
license-private.key
```

### 3. 重新编译

```bash
swift build
```

公钥已写入 `LicensePublicKey.swift`，编译后生效。

### 4. 验证配置正确

```bash
swift run licensegen selfcheck
```

应输出 8 项全部通过。

## 四、日常发码

### 方式一：命令行（适合批量）

```bash
cd /Users/meteor/github/XNook

# 签发 100 个销售码，导出 CSV
swift run licensegen issue \
  --key ~/.xnook-license/license-private.key \
  --count 100 \
  --start 1 \
  --csv batch-001.csv

# 签发 10 个早期支持者码
swift run licensegen issue \
  --key ~/.xnook-license/license-private.key \
  --count 10 \
  --start 101 \
  --early-supporter \
  --csv batch-002-early.csv

# 校验某个码是否有效
swift run licensegen inspect --public <公钥文件> "XNK1-..."
```

### 方式二：管理后台（适合零散发码与查台账）

```bash
cd /Users/meteor/github/XNook

XNOOK_ADMIN_TOKEN=$(openssl rand -hex 32) \
XNOOK_PRIVATE_KEY=~/.xnook-license/license-private.key \
node Tools/admin/server.js
```

打开 `http://127.0.0.1:8787`，填入终端打印的令牌即可使用。

后台提供：

- 生成邀请码（可选销售码 / 早期支持者 / 人工赠码，带备注便于对账）
- 台账总览（已生成 / 已售出 / 已激活 / 下一个序列号）
- 按序列号查询单个码，含一键激活链接
- 导出 CSV
- 查看激活登记记录

**服务只监听 `127.0.0.1`**，外部无法访问。这是刻意的默认值——避免你在没配 HTTPS 的情况下把它暴露到公网。

## 五、怎么把软件卖出去

### 关键认知：你不需要自己写购买网站

个人开发者卖 Mac 软件，国内通行的做法是**预生成码 + 发卡网自动发货**：

1. 用上面的方式批量生成 100 个码，导出 CSV
2. 把 CSV 上传到发卡平台（如自动发卡网），设置单价
3. 买家付款后，平台自动发一个码给买家
4. 你在后台看到该码被激活

**整条链路不需要服务器、不需要支付资质、不需要备案。** 成本接近零。

### 为什么不建议自己接支付

- 微信支付 / 支付宝的**商户号需要企业或个体工商户资质**，个人无法直接开通
- 如果走个人收款码，无法自动发货，且存在合规风险
- 发卡平台已经解决了这个问题，你只需要提供码

### 定价参考

| 档位 | 价格 | 说明 |
|---|---|---|
| 早期支持者 | ¥29–49 | 限量，带 `earlySupporter` 标志 |
| 正式版 | ¥68–98 | 一次性买断，永久使用 |
| 赠码 | ¥0 | 朋友、评测者、KOL，带 `complimentary` 标志 |

一次性买断 + 永久授权，是这类工具软件最容易被接受的模式。避免订阅制——除非你能持续交付新功能。

## 六、在线登记（可选）

默认**不启用**。不启用时软件完全离线运行，激活不产生任何网络请求。

如需启用（用于统计卖了多少、激活了多少），在 `Info.plist` 中加入：

```xml
<key>XNookLicenseEndpoint</key>
<string>https://your-domain.com/api/activate</string>
```

启用后，App 在**首次激活时**上报一次：序列号、短编号、版本号、平台。**不含任何个人身份信息。**

上报失败被静默忽略，**不影响激活结果**。这是刻意的：登记是增量信息，不是放行前提。

### 部署登记端点

管理后台已内置该接口。若要让 App 从公网访问，需要：

1. 一台有公网 IP 的服务器（最便宜的云服务器即可，或家里的树莓派 + 内网穿透）
2. 用 Nginx/Caddy 做 HTTPS 反向代理到 `127.0.0.1:8787`
3. 只暴露 `/api/activate`，**不要暴露 `/api/admin/*`**

Caddy 配置示例（自动申请证书）：

```
your-domain.com {
    handle /api/activate {
        reverse_proxy 127.0.0.1:8787
    }
    respond 404
}
```

> 注意：即使暴露了 `/api/admin/*`，没有令牌也无法调用。但最小暴露面仍是更好的做法。

## 七、这套机制能防住什么、防不住什么

**必须讲清楚，因为这决定了你该投入多少精力在这上面。**

### 能防住的

| 场景 | 结果 |
|---|---|
| 有人随便编一个码 | 防住——验签必然失败 |
| 有人篡改码里的序列号 | 防住——签名失效 |
| 有人读源码想自己造码 | 防住——没有私钥造不出有效签名 |
| 用户删 `UserDefaults` 重置试用 | 防住——双位置冗余，两处都删才能重置 |
| 用户把系统时钟调回去 | 防住——取 `max(系统时间, 记录时间)` |
| 用户手工伪造已激活凭证 | 防住——恢复时重新验签 |

### 防不住的

| 场景 | 说明 |
|---|---|
| **源码可见 + 可自行编译** | 任何人下载源码，把 `LicenseManager` 的检查注释掉重新编译，即可绕过一切限制。这是 source-available 的固有代价。 |
| **码被分享** | 你选了「一码通用、不绑机器」，因此一个码可以在任意多台机器激活。在线登记能让你**看到**异常，但无法阻止。 |
| **两处记录都删** | 纯本地方案的共同上限。删掉 `UserDefaults` 键 + `~/Library/Application Support/XNook/.state/install-anchor` 即可重置 14 天试用。 |
| **内存补丁** | 附加调试器修改运行中的内存，可以绕过任何本地检查。 |

### 结论：这套机制的目标是「阻止随手分享」，不是「防破解」

这两者的成本差距是数量级的：

- **阻止随手分享**：当前方案已实现，成本几乎为零
- **真正防破解**：需要代码混淆、完整性校验、服务器心跳、反调试——而且**在源码公开的前提下依然做不到**

所以不要在这上面继续投入。如果你的目标是「绝对防盗版」，唯一有效的办法是**闭源**——但那会失去 source-available 带来的所有好处（社区信任、技术展示价值、简历素材）。

以你目前的定价（几十元）和目标（主要是让软件有个正规的获取渠道，同时保留开源的技术展示价值），**当前强度是合适的**。

## 八、用户侧体验

### 正常流程

1. 用户下载 DMG，首次启动 → 自动进入 **14 天试用**，全部功能可用
2. 设置 → 授权，可随时看到「试用中 · 剩余 N 天」与进度条
3. 试用期内或到期后，在授权页粘贴邀请码 → 点击激活 → 立即生效
4. 也可以直接点击购买邮件里的 `xnook://activate?code=...` 链接，一键激活

### 到期后

试用结束（第 14 天）后启动：

- **不创建灵动岛窗口**——这是真正的硬锁，不是弹个可忽略的提示
- 显示独立的激活窗口，可复制粘贴邀请码
- 窗口层级置顶，但仍可切换应用去复制码（刻意不用模态弹窗，否则用户无法切窗口）
- 激活成功后**自动恢复正常启动流程，无需重启**

### 用户可用的排障入口

- 授权页有「从剪贴板粘贴」按钮，避免手抄 116 字符
- 激活失败会给出**具体原因**（长度不对 / 含无效字符 / 签名无效），而不是笼统的「无效」
- 已激活用户可「解除激活」（换机或排障用）

## 九、常见问题

**Q：用户换电脑了怎么办？**
A：直接在新机器上输入同一个码即可。当前是「一码通用、不绑机器」策略。

**Q：能限制一个码只能激活 3 台设备吗？**
A：技术上需要服务器参与判定，与「放行在本地」的原则冲突。不建议。

**Q：想撤销某个泄露的码怎么办？**
A：当前**无法撤销**——码一旦签发就是永久有效的。若确实需要，只能：(1) 换密钥对重新发码（已发出的全部失效，代价极大）；(2) 引入在线黑名单（但断网用户仍可用，且违背本地放行原则）。**因此发码时要谨慎，不要把码公开贴出。**

**Q：忘记发到哪个序列号了？**
A：管理后台的台账记录了每个批次与序列号区间，`ledger.json` 也在数据目录里。

**Q：`licensegen` 会随 App 分发吗？**
A：不会。它是独立的可执行目标，只在你本机运行，不打包进 `.app`。

**Q：试用期从什么时候开始算？**
A：从**首次启动**算起。注意：重新安装 App 不会重置——锚点存在 `~/Library/Application Support/XNook/.state/`，卸载 App 时不会被删除。
