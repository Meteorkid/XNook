## 已复现并修复的问题

| 问题 | 修复前证据 | 本地修复 |
| --- | --- | --- |
| 解绑返回明确无效设备仍继续接受缓存 | 401/403/404/410 后当前会话及冷重启仍为 active，共 8 个失败断言 | refresh 与 deactivate 共用明确失效处理，持久化阻止访问状态 |
| 服务端解绑成功但凭据写入失败，核心仍为 active | 200 成功响应后注入保存失败，核心状态没有及时关闭 | 收到服务端确认即关闭当前访问，存储错误保持关闭；XNook 原适配器的随后 refresh 可缓解旧问题，不能据此忽略共享 API 的状态缺陷 |
| 临时安全存储故障恢复后无法重试 | 初次读取或后续写入恢复可用后，start 仍被永久的 storageFailed 标志挡住 | 读取失败先重读并完整解码；写入失败优先保存内存中已确认的撤销/解绑状态，不用旧缓存覆盖它 |
| 停止监控后迟到请求仍写入凭据并重新激活 | 首次试用与手动激活的延迟成功响应在 stop 后触发 active，并保存 deviceToken | 统一持有请求 Task，取消传播到协议层；停止标志与请求代次阻止迟到 UI 回调及重新挂定时器 |
| 旧码迁移或空码错误在页面刷新后丢失 | 方法返回 failure，但 lastError 为 nil；模拟授权页 onAppear 的 refresh 后仍丢失 | 核心预校验保存本次诊断，适配器先同步状态再保留操作错误；成功刷新同一租约会清除旧错误 |

功能修复仅修改 `SoftwareLicenseSession.swift` 与 `LicenseManager.swift`；随后按要求统一了授权视图、本地化文案和 `SoftwareLicense.swift` 的旧码诊断。现有服务端协议与持久化 Record 格式不变；生产构造器继续使用真实 Date、NSWorkspace 与 Keychain，测试注入没有增加命令行或环境变量放行入口。

## 新增验证

新增 26 个反例/边界用例：共享核心 14 个，XNook 生命周期 12 个。连同既有 20 个授权测试，**Debug 46/46、Release 优化构建 46/46，均无失败或跳过**；两轮都加载了网站生成的签名 fixture。

补充完整回归：`swift test` 运行 XNook **1213 项（1119 通过、94 项既有环境/可选跳过、0 失败）**，共享核心 **31/31 通过**；合计 1244 项、1150 通过、94 跳过。全量日志见 `.build/license-audit-20261027/full-verification.log`，未为获得通过而修改无关测试。

覆盖范围：

- 首次离线不能开始试用，恢复网络可重试；请求字段与产品/设备绑定保持一致。
- 永久授权离线租约在整 7 天边界到期，月/年使用权不能被租约延长；已记录的过期状态不能在回拨时钟和冷重启后恢复。
- 误设未来时间后可由新近已验签在线响应重新校时；旧在线响应不能执行校时。
- 错产品、错设备、篡改签名/缓存不替换已有有效凭据；坏缓存不会被当作新用户试用。
- 调用者取消与停止监控均会取消内部请求，迟到成功响应不落盘；离线解绑失败保留原有效凭据，可恢复网络后重试。
- 明确撤销、解绑确认后的写入失败、临时读取/写入故障恢复，以及恢复过程不能复活已确认撤销、不能覆盖无法解码的旧记录。
- 停止后拒绝新请求，取消后可以重新开始监控；成功刷新相同租约清除旧错误。
- 试用状态不提供付费设备解绑，三种付费期限提供相应状态与到期说明。
- 常驻精确定时器到期锁定；模拟唤醒时先关闭过期访问，再等待网络响应。
- 笔记保存失败后仍保留内存内容、阻止静默退出，并可导出最新内容，原存储文件字节不变。

## Release 参数旁路检查

产品源码未发现 `CommandLine.arguments`、`ProcessInfo.processInfo.arguments`、`--ui-test-mode` 或 `publicKeyOverride` 授权放行路径。发布时的 1.3.26 二进制也没有 `--ui-test-mode`、`METEOR_LICENSE_FIXTURE_PATH`、`publicKeyOverride` 字符串。本轮进一步以 `-c release` 编译并运行同一组隔离授权测试，缺公钥、无有效签名、到期和停止状态仍关闭访问。

这属于源码/发布二进制检查与 Release 模块测试；没有启动会访问用户 Keychain 的正式 App，不能写成“真实安装包 UI 已完整验收”。
