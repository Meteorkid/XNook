## 一、检索范围与方法

### 1.1 检索目的、判定基准与编号警示

本轮针对核心技术方案 **F1–F6** 逐项确认区别特征是否已被公开。**须特别注意**：本任务定义的 F1–F6 系「证据优先级链 + 首帧时限」方案（源自 `LIVE-CAPTION-BREAKTHROUGH-BRAINSTORM.md` 第五、十、十一节与 `LIVE-CAPTION-NEW-METHOD-SEARCH.md` 第四节），与 `PATENT-DRAFT-系统级字幕调度.md` 旧草稿中的 F1–F6（「可预取度 + 双前沿差闭环」）**编号相同、内容不同，不可混用**。本分片一律以本任务给出的 F1–F6 为准：

| 编号 | 技术特征（本分片判定基准） |
| --- | --- |
| F1 | 统一证据提供者接口：每个来源声明证据等级、可预取性要求、是否允许异步、产出时间区间、估计耗时、超时降级动作；所有候选统一按绝对源时间戳索引 |
| F2 | 由音源描述符（进程标识、播放前沿、播放速率、后续音频可提前读取标志）计算可预取度 P；据此动态剪枝证据链：P 高时把耗时来源前移到播放前执行并缓存命中结果，P 低时从链中移除要求可预取的来源、链长随之缩短 |
| F3 | 设置首帧时限 D = t_audio + L_budget（可配置，如 300 ms）；到达时限时不等未完成来源，用当前已就绪的最高证据等级候选渲染 |
| F4 | 超时后到达的证据只允许写入其时间区间中尚未进入已读状态的后续区间，经收敛状态按证据权重更新，不回改已呈现条目 |
| F5 | 轨间切换边界限定在已稳定条目；音源变化或播放跳变时用音频指纹重锚时间轴并仅补处理未覆盖区间 |
| F6 | 可选：以「未确认高后果位占比」为定向预算控制量，把推理预算投向专名/数值/术语位置 |

### 1.4 判定口径与符号约定

- `●` 完全覆盖：已明确公开该特征的实质内容；`○` 部分覆盖：公开了相近理念、单一环节或部分字段，但缺少关键限定；`—` 未覆盖：本轮检索范围内未见公开该特征。

**K02 `US8775174B2` — Method for indexing multimedia information（注意：真实主题为多媒体信息索引）**
- 授权 / 公开日 **2014-07-08**；申请日 2011-04-27；优先权 2010-06-23；申请号 US13/095,388。同族公开 `US20110320197A1`（2011-12-29）。

- 本次核实到的原文要点：以「**a priori** 选择声学/语言模型」的 **Convergent ASR** 替代 a posteriori 自适应；迭代过程获得更准确转写；说话人分离（VAD/BIC/LLR）选声学模型；「文本表示来自字幕，或来自前次转写运行结果」，用于文本分离与选择更好的语言模型；字幕以 pseudo-sentences / close-caption lines 形式携带时间信息；新闻索引、聚合与聚类。
- **差异警示（2026-11-14 已核实，结论：半分——「补空白」成立，「覆盖率图」不成立）**
  - **「补空白」成立**。说明书在发明目的段与聚合器模块（FIG. 4）中明确记载：检测既有字幕中的 `"blanks"`，其定义为**长于某一应用相关阈值的时间跨度**（示例 15 s；更短的空白可能来自音乐前奏、有时被误判为语音而送入 ASR）；对每个 blank，用 ASR 的输出填充；为确定填充起点，把 ASR 输出中的候选句与 blank 之前的最后一条字幕（称 `reference sentence`）比对，候选限于起始时间落在某一重叠阈值内的句子，并按文本相似度确定对齐点；blank 末尾同法处理（重叠阈值不同，因字幕起点通常比终点更准）；最后修正边界处时间戳以避免时间重叠。原文：`the new transcription is appropriately added to the original subtitles, filling the gaps`、`For every "blank", it is filled with the output of the ASR`。

### 2.4 学术预印本（A 组，均非专利、非字幕实时场景，仅作「理念已公开」佐证）

**A01 arXiv 2608.14509「Split the Labor: Separating Evidence Interpretation from Decision Aggregation」**（2026-08；同行评议状态未核实）：提出把「解读每个来源」与「聚合结论」用**固定证据接口**分离；四字段证据元组 `(hypothesis, reliability bucket, rationale, provenance)`；可靠性由读取操作的可观测属性估计；以 weight-of-evidence 分解 posterior log-odds、池化校准后的对数似然比；指出「对未归一化权重求和设阈值」会随来源数漂移。对应 F1 ○（统一证据接口、可靠性分桶、证据权重聚合概念已公开；但缺 F1 的「可预取性要求 / 是否允许异步 / 产出时间区间 / 估计耗时 / 超时降级动作 / 绝对源时间戳」全部工程字段）、F4 ○（对已存储 evidence objects 重新聚合、按来源可靠性更新）。

### 4.3 未见公开的理由

1. **场景边界互不重合**：现有文件分别落在单一本地文件 + 自带播放器（Myna，输入恒可预取、无证据等级仲裁）、单一 ASR 轨内的 partial/final 或双解码分支（S03、`CN116635932B`、`US12254869B2`，来源单一）、识别权重/算力分配（`US20120290298A1`、`CN202511057472`、`CN122334404B`，优化目标非「来源链编排 + 延迟上界」）、离线索引或质量监控（`US8775174B2`、N01，无实时呈现时限与已读状态）、跨领域学术抽象（A01–A05，虽公开「固定证据接口」「优先级单调更新」「已完成不回滚」，但未与绝对源时间戳、可预取度、首帧时限、指纹重锚组合）。**没有一件把上述要素放进「应用无关、音源身份可变、多异构来源并存」的同一系统级实时字幕调度闭环。**
2. **组合动机不足**：现有技术把「可预取性」当作前瞻预算的调度量（旧草稿、Myna）或根本不判定（Myna 输入恒可随机访问），没有动机把它提升为「决定证据链长度与来源准入」的一等属性；也没有动机用「首帧时限」把多来源仲裁的输出延迟上界与来源数量解耦。
3. **协同效果非单点可得**：C1–C6 组合后「输出延迟上界与来源数无关、重复转写与峰值内存/缓冲数据量同时下降、推理单元利用率上升」的系统内部性能改进，不是任一单点特征能单独获得的；现有技术分别优化准确率、延迟或算力，未以「来源链编排」为共同目标。

5. **F5**：把技术目的与效果写为「避免重复处理 / 仅补处理未覆盖区间」而非「校正字幕时间偏移」（与 `US10021445` 划界）；切换边界限定「**已稳定条目**」并明确为「**多来源证据轨之间**」（与 N02/N03 的字幕文件/语言切换划界）。**（2026-11-14 增补）** `US8775174B2` 已公开「检测既有字幕 blank 并只用 ASR 填充该空白」，故**不得只写「仅补未覆盖区间」**——该表述本身已无区别。须写成两层限定：① 补处理范围由**时间轴覆盖图上逐区间的状态量**（已覆盖／冲突／未覆盖／已读）界定，而非由「既有字幕的时间空档阈值」界定；② 补处理由**进程标识变化或播放前沿跳变 ＋ 指纹重锚**触发，而非由离线批处理触发。上述重锚与「仅补未覆盖区间」的具体手段**置从权、不进独权**（见 6.3 第 6 项），本条效果写法同时适用于该从权。
6. **F6**：**建议不进独权**；若保留从权，须把控制量明确为「未确认高后果位占比」并排除「语义重要性评分 / 风险状态 / 显著性权重 / 置信度」，且技术效果落在系统内部性能。仅作为说明书内部质量状态量与评测口径，不作区别技术特征主张。
7. **整体**：独权前序写入「应用无关的系统级、音源身份可变、多种字幕来源并存」（与 Myna 单一本地文件 + 自带播放器划界）；有益效果统一写成系统内部性能，不出现「用户看得更准/更舒服」等体验性表述。

### 6.3 独权应保留的限定（供 `claims-writer` 取用）

**必须作为必要技术特征保留（缺一即可能被在先公开逐项拆解）**：

1. **前序环境限定**：由包括本地推理单元与存储器的计算设备、在**应用无关、音源身份可变**的系统级环境下，取得当前播放音频与相关信息；**多种字幕来源并存**（应用发布的文本流、媒体元数据、音频指纹检索到的既有全文、画面文字识别结果、流式语音识别结果）。此限定用于与 Myna Player「单一本地媒体文件 + 自带播放器」划界。
2. **F1 全字段**：各来源按统一证据提供者接口声明「证据等级、可预取性要求、是否允许异步、产出时间区间、估计耗时、超时降级动作」，**全部候选统一按绝对源时间戳索引**。
3. **F2**：由音源描述符计算可预取度 P，**据此动态剪枝证据链**——P 高时把耗时来源前移到播放前执行并缓存命中结果，P 低时从链中移除「要求可预取」的来源、**链长随之缩短**；剪枝依据限定为 P，排除内容类型/置信度/延迟容忍度/语义重要性/难度。
4. **F3**：设置 **D = t_audio + L_budget**（可配置常量）；到达 D 时**不等未完成来源**，**用当前已就绪的最高证据等级候选**渲染。
5. **F4**：超时后到达的证据**只允许写入其时间区间中尚未进入已读状态的后续区间**，**经收敛状态按证据权重更新**，**不回改已呈现条目**（已读状态须可机器判定）。
6. **F5（独权仅保留边界限定）**：轨间切换边界**限定在已稳定条目**，各候选轨统一按**绝对源时间戳**索引。**「检索匹配锚点并据此把播放前沿映射到已有转写结果」「仅补处理未覆盖区间」「以音频指纹重锚时间轴」均置从权**（对应 `02-claims.md` 权 9 及 team-lead 原始指令：重锚列为从权主题、独权不塞入过多可选限定以免过窄）；该从权的目的与效果写为「复用已完成窗口、减少重复推理」，而非「校正字幕时间偏移」。理由：`US10021445`、Myna 的 seek 复用、N02/N03 已公开指纹时间差传播与按时间戳切换单点，若写入独权会增加被逐项击破风险；独权只保留「已稳定条目边界」这一可与 `US10021445`、N02/N03 划界的最小必要限定（与项目矩阵第六节 D1 规避建议、`02-claims.md` 权 1／附四第 5 组一致）。
7. **技术效果口径**：减少重复转写次数、降低峰值内存占用与音频缓冲数据量、提高推理单元利用率、**把输出延迟上界约束为与来源数量无关的可配置常量**；**不写用户体验**。

**不应写入独权 / 不作为区别特征主张**（单点均已公开）：系统级音频捕获本身、平台字幕接口调用、主/辅引擎并行、长短前瞻缓冲、词列表拼接与类模型豁免、指纹时间差传播、重叠窗口去重、按语义重要性/显著性分配算力、热词偏置、字幕文件/语言切换、浮层 UI 呈现、双语翻译、**F6（至多从权或说明书实施例）**。

## 七、背景技术段落建议（可直接写入说明书）

> 以下为客观陈述，不贬低在先技术，技术问题与技术效果均落在系统内部性能；汉字约 366、含标点约 393 字符，落在 250–400 字区间。正式提交前须由代理师按申请文件格式改写，并补齐引用文件的公开号。

操作系统提供系统级音频捕获能力后，可为任意播放中的应用生成字幕。系统可同时取得应用文本流、媒体元数据、指纹检索全文、画面文字识别与流式识别结果等多种来源，各来源独立产生带时间区间的候选。已有公开方案分别就提前转写与规范时间窗缓存、主辅引擎并行的长短前瞻合并、可变前瞻、字幕未覆盖区间填补、指纹锚点校正时间轴，以及按词显著性或语义重要性分配算力等侧面给出方案，在各自适用范围内有效。但多种来源并存时，并行全量处理会对同一区间重复转写，使峰值内存与音频缓冲数据量上升、推理单元利用率下降；等待全部来源到齐再仲裁则延迟受最慢来源支配，难以约束于实时呈现时限。且音源在后续音频能否提前读取上存在差异，固定长度处理链在不可预取音源上会执行无效重计算。因此，如何在多来源并存、可预取性动态变化的系统级环境下，以与来源数量无关的时延上界完成仲裁并抑制重复转写与无效缓冲，仍是待解决的系统内部调度问题。
