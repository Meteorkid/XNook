## 一、结论先行

本轮针对「更高效更准确」新做了 9 组检索，逐个核查四个候选方向。**四个方向全部命中已公开文献，最早可追溯到 2003 年**。因此：

- **专利层面**：没有一个「新的单点发明」能同时提效提准且未被公开。继续在「找更巧的识别算法」上投入，边际收益很低。这一结果反而印证了 `PATENT-DRAFT-系统级字幕调度.md` 的收窄方向是对的——剩下的空间只在「把已有手段按可预取性/覆盖率动态编排、以系统内部资源节省为闭环目标」的组合层面。
- **工程层面**：**有明显更优的实现**，但不是新算法，而是换掉「默认要跑 ASR」这个前提。上一版三轨架构把整段音频都送进识别轨；更优的做法是先汇聚所有已存在的字幕信息，生成时间轴覆盖图，把 ASR 从默认动作降为**兜底动作**。

一句话：**要提效，就少识别；要提准，就让文本层纠错和全局一致性去做，而不是堆更大的声学模型。**

## 三、工程上更优的流水线（五层）

核心前提：**字幕是文本，文本往往已经存在，只是散落在不同位置、且时间轴可能不准。** 全部已有方案（包括本项目初版）都把 ASR 当主路径，只在命中缓存时跳过；而真实场景里字幕信息常以多种形式**部分存在**。把它们先汇聚成一张时间轴覆盖图，系统就能在播放开始前算出「哪些区间根本不需要推理」。

### L0 · 字幕可得性探测 → 时间轴覆盖图

并行探测六类来源：容器内嵌字幕轨（CEA-608/708、WebVTT、TTML、PGS、ASS、mov_text）、平台字幕接口、sidecar 字幕文件、按媒体指纹检索的本地/远端字幕库、烧录硬字幕的 OCR（只对必要帧）、以及本地已转写缓存。

每个来源返回其覆盖的时间区间集合，合并为**覆盖图**，把媒体时间轴划为三类：

- **已覆盖**：至少一个来源有文本 → 零推理，直接取用；
- **冲突**：多个来源都有文本但不一致 → 不重跑 ASR，用强制对齐计算各候选文本与该段音频的声学似然或文本相似度，取最贴合者；
- **空白**：所有来源均无文本 → 才进入 L1。

平台字幕经常**只有部分**有（AI 字幕漏时段、CC 字幕漏歌曲音效、双语字幕只有一种语言），二值「命中/未命中」判断会退化成全量 ASR；覆盖图能只补缺口。

### L1 · 缺口定向轻量识别

只对空白区间跑轻量流式模型（Zipformer / FunASR 一类），输出带**词级后验概率**与绝对源时间戳的文本。两个可选提效点：

- **难度预判前置**：在解码前用信噪比、语速、基频方差等廉价信号判断片段难度，直接选模型档位，省掉「先跑一遍再看置信度」的那一遍（该思路见 `CN121309899A`，已公开，仅作工程手段使用）。
- **邻域上下文**：抽取窗口时前后各扩展约 2 s 作解码上下文，但输出只归属规范窗口，避免边界词丢失或重复（Myna Player 已公开）。

### L2 · 文本层生成式纠错（替代二次声学解码）

对**低置信片段**不重跑声学模型，而是把「首轮文本 + 前后文 + N-best 候选 + 拼音/音素表示 + 全局实体表」交给一个小语言模型做保守改写。理由：中文 ASR 的残留错误以**同音字与专有名词**为主，这是语言学问题而不是声学问题；文本 token 的推理成本比音频帧重解码低一个数量级。

必须加的门控（否则负收益）：只改低置信片段、只修明显错词、保留原时间戳、拼音/音素一致性校验（改后拼音需与原文一致或在允许的音素邻居集内）、改写率监控、保留原文可回退、上线前 1% 人工抽检。

### L3 · 全片实体一致性投票（只有可预取音源能做）

首轮全片转写后建立实体表：人名、地名、术语及其在全片的出现位置与各自置信度。对声学特征相近的多个出现实例聚类，用置信度最高的实例统一其余实例；若某低置信实例能在全片找到高置信的同一实体，**直接替换，连 L2 都不用跑**。

这是「提前识别」真正独有、而 Myna Player 与现有双引擎方案都没有利用的红利：只有能看到全片，才谈得上全局一致性。跨窗口独立转写无法做到。

### L4 · 统一时间轴仲裁与输出

各轨统一按绝对源时间戳索引；同一区间按「来源等级 + 词级后验概率 + 时间连续性」取置信度最高且状态为已稳定的条目；轨间切换边界限定在已稳定条目处，已输出条目不回退修改。

**音源分派**：可预取音源在播放前跑完 L0–L3，播放时纯读取；不可预取音源退化为 L1 + L2 的短前瞻链路，L0 只做本地缓存查询，L3 降级为滑动窗口内的短期一致性。

## 五、与初版设计（`LIVE-CAPTION-DESIGN.md`）的差异

| 维度 | 初版三轨 | 分层流水线 |
| --- | --- | --- |
| 默认动作 | 拿到音频 → 选一条识别轨 | 拿到音源 → 先探测已有字幕，ASR 只作兜底 |
| 命中判断 | PlatformTrack 二值命中/未命中 | 多来源时间轴覆盖图，区分已覆盖/冲突/空白 |
| 精修方式 | 快轨 + 大模型精修轨全量并行 | 文本层生成式纠错，只处理低置信片段 |
| 上下文利用 | 窗口内 ±邻域音频 | 额外增加「全片实体一致性」，仅可预取音源可用 |
| 算力模型 | 100% + 100% 双路推理 | 零推理区间 + 定向轻量推理 + 文本级纠错 |
| 主要风险 | 算力与内存浪费、专名仍靠热词硬扛 | 字幕来源质量参差、LLM 幻觉、覆盖图对齐误差 |

这不是推翻初版：三轨调度、绝对源时间戳、Volatile/Stable/Corrected 三态、指纹重锚、权限工程踩坑等结论仍然有效，L4 直接复用初版的合成层与呈现层设计。**被替换掉的是「默认全量 ASR」这一层，以及「用大模型重跑音频来提准」这个手段。**

## 六、对专利工作的影响（重要）

1. **不要把本轮任何方向写进权利要求**。`US20030120486A1`（2003）、`US8775174B2`（2014）、`US20260246893A1`（2026）等已把它们公开得很彻底。
2. **反而支持了草稿的收窄方向**。既然所有「更聪明的单点」都已被公开，剩下的空间确实只可能在组合编排层面，即 `PATENT-DRAFT-系统级字幕调度.md` 的 F1–F6。这一点让上一轮的收窄决定更站得住，不需要推倒重来。
3. **但有两件新增对比文件会削弱草稿权 7**：`CN121309899A`（按识别难度与算力自适应选模型）与 `US20240395244A1`（按准确率评分 + 功耗/算力成本选模型）已公开「算力预算驱动模型选择」。建议代理师评估：是否把独权的闭环控制量进一步限定为「由多来源字幕覆盖图导出的**待推理时间区间占比**」，而不是泛泛的「推理单元负载 U」。这样与这两件的区别更清楚。
4. **可以考虑补一项从权**：把「覆盖率图 → 前瞻预算」的关系写进去（例如「当前瞻预算计算时，把已覆盖区间从待推理时长中扣除」）。这仍属组合层面，但能把工程上真正的提效机制纳入保护范围。
5. **披露风险不变**：本文同样位于 `docs/`，正式提交前不要推送到公开仓库。

## 七、风险与约束（不能只讲好处）

1. **LLM 纠错会幻觉**：会把口语改成书面语、把对的改错。字幕场景要求「忠实转写」，过度润色是负收益。必须靠保守改写门控 + 拼音约束 + 改写率监控 + 保留原文，而不是靠提示词里写一句「不要乱改」。
2. **OCR 成本高**：行业文章给出的量级约为 ASR 的 20 倍，只应在「低置信片段对应帧」上按需调用，不能全片跑。
3. **字幕来源质量参差**：平台 AI 字幕本身可能有错，用户上传字幕可能时间轴错位。覆盖图必须带来源等级与置信度，且冲突区间不能简单「取平台字幕」。
4. **覆盖图对齐误差**：不同来源时间轴基准可能差 1–5 s（`US8775174B2` 专门处理过这个），需要锚点词/指纹对齐后才能合并，否则会在边界处产生重复或漏字。
5. **L3 只对可预取音源有效**，直播场景退化为滑动窗口内一致性，收益有限。
6. **所有数字未在 M3 Max 上实测**。上表除标注为公开论文数据的行外，均为估计或量级参考，不能当结论。

## 八、落地优先级（若要在 XNook 里实现）

按「收益 / 工作量」排序，建议分四步走，不要一次性重写：

| 顺序 | 动作 | 预期收益 | 依赖 |
| --- | --- | --- | --- |
| 1 | **L0 覆盖图 + 多来源探测**（先做容器内嵌轨、sidecar、平台接口、本地缓存四类） | 立刻把热门点播的 ASR 调用降到只剩缺口；成本最低、收益最大 | 复用现有 `CaptionSourceAdapter` 抽象 |
| 2 | **L1 缺口定向识别 + 难度预判**（把整段均匀切窗改为按空白区间建任务） | 消除对已覆盖区间的无效推理 | 步骤 1 的覆盖图 |
| 3 | **L3 全片实体一致性**（只在可预取轨启用） | 中文人名/术语一致性，专名准确率提升且不增加推理量 | 需要全片首轮结果 |
| 4 | **L2 文本层纠错**（最后做，因为风险最高） | 处理同音字残留错误 | 需要词级置信度与可靠的门控/评测集 |

**建议先做一个最小评测集**（20–30 段中文视频，覆盖有字幕/无字幕/部分字幕/直播四类），量化三个指标：零推理区间占比、CER、端到端呈现延迟。没有这套基线，任何「更准」的说法都只是推测。本机 M3 Max / 36 GB 的算力余量足以跑完整链路，但功耗与风扇表现同样要测。
