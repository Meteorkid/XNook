# X Nook v1.3.34

发布日期：2026-11-17

上一版把六项权限收进了一个页面，但「拖拽添加」还差半步：图标在主窗口里，系统设置一打开就盖住主窗口，用户得先把窗口挪开、或去 Finder 里翻应用。本版把这一步补完——**点一下，图标自己浮到系统设置旁边**。

## 一步拖到位

在「设置 → 权限」里点任意一行的「打开系统设置」，或点顶部卡片上的「打开并浮起图标」：

1. 系统设置打开到对应分页（例如「屏幕录制」）。
2. 一个窄条浮板出现在系统设置窗口左侧，里面就是 X Nook 的图标。
3. 按住图标拖进右侧列表——和把 App 拖进「应用程序」文件夹是同一种操作。

拖进列表后浮板自动收起，系统会提示「退出并重新打开」以使屏幕录制生效（权限页同时给出「立即重启」按钮）。

### 浮板为什么不是普通窗口

系统设置是普通窗口层级的应用，只要它在前台，主窗口就在它后面。所以浮板做成了非激活面板：

| 属性 | 取值 | 作用 |
| --- | --- | --- |
| `styleMask` | `.borderless` + `.nonactivatingPanel` | 出现时不抢系统设置的焦点 |
| `level` | `.floating` | 始终压在系统设置窗口之上 |
| `becomesKeyOnlyIfNeeded` | `true` | 只有需要输入时才取键盘焦点 |
| `hidesOnDeactivate` | `false` | 切到别的应用也不消失 |
| `collectionBehavior` | `.canJoinAllSpaces` + `.fullScreenAuxiliary` | 跨桌面、跨全屏空间可见 |
| `isMovableByWindowBackground` | `true` | 挡住内容时可以随手挪开 |

鼠标按下能被非激活窗口接收，靠的是拖拽视图里 `acceptsFirstMouse` 返回 `true`——否则第一次点击只会用来激活窗口，拖不起来。

### 位置怎么算的

系统设置的窗口位置用 `CGWindowListCopyWindowInfo` 取（按 owner 名匹配 `System Settings` / `系统设置`，取面积最大的那个窗口）。这份 API 的坐标原点在左上、y 向下，而 AppKit 的窗口坐标原点在左下、y 向上，所以要用主屏高度翻一次：

```swift
let primaryHeight = NSScreen.screens.first?.frame.height ?? rect.maxY
return CGRect(x: rect.minX, y: primaryHeight - rect.maxY, width: rect.width, height: rect.height)
```

浮板贴在窗口左侧、顶部对齐；左边放不下（窗口贴屏边）时退到屏幕边缘；完全找不到窗口（系统设置冷启动慢）时退到屏幕右上角。高度用 `NSHostingView.fittingSize` 夹在 140–220pt 之间，不再拖出一块空白。

### 提示语指向具体列表

浮板上写的是「拖到右侧『屏幕录制』列表」而不是「拖到右侧列表」——不同分页的列表名不同（语音识别、日历、自动化），笼统的说法在第一次用的时候等于没说。文案取自 `SystemPrivacySettings.Pane.listTitle`，与深链共用一份定义。

## 深链：`xnook://permissions`

引导文案、帮助文档、客服话术可以直接引用，把用户送到「已打开分页 + 浮起图标」的状态：

```text
xnook://permissions?pane=screenRecording
```

`pane` 可选 `screenRecording`（缺省）、`speechRecognition`、`calendars`、`automation`、`accessibility`、`loginItems`、`privacy`。

## 顺带

- 权限页显示当前运行实例的真实路径，并提供「在 Finder 中显示」。同时装了两份（`/Applications` 与 `.build`）时，能一眼确认拖的是哪一个。
- 移除开发期用于验收浮板的临时钩子。

## 已知：更新后首次启动的一次性弹窗

本版沿用 v1.3.33 引入的固定自签名身份。之前版本是 ad-hoc 签名，钥匙串里的授权码条目只信任当时的二进制；身份换了之后，**第一次启动会弹一次钥匙串询问**（「X Nook 想要访问您钥匙串中的密钥 com.meteorkid.xnook.software-license」）。

点「始终允许」即可，之后所有版本都不会再问——这与系统授权（TCC）跨版本继承是同一套机制：代码签名的 designated requirement 从 cdhash 换成了「identifier + 证书叶哈希」。

## 验证与安装包

- 安装包：`XNook-1.3.34.dmg`，Apple Silicon（arm64），macOS 14 或更高版本。
- 签名：本地自签名证书 + Hardened Runtime，未使用 Developer ID，未公证。首次打开如被 Gatekeeper 拦截，请右键「打开」。
- 发布前全量测试：XNook **1311 项，101 项条件跳过，1 项环境性失败**（`GifResourceTests.testLegacyBookmarkReadsThroughTheSameBudget`，SwiftPM 测试宿主缺 `com.apple.security.files.bookmarks.app-scope`，与 v1.3.33 相同，可用 `scripts/test-signed-bookmarks.sh --filter GifResourceTests` 在带签名的宿主里验证）。
- 浮板定位在测试宿主里实测：系统设置窗口 `(351, 148, 723, 712)` → 浮板落在 `(207, 635, 132, 197)`，贴边间距 12pt。
