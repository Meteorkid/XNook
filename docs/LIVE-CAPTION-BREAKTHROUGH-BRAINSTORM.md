## 一、范式总纲

前四轮所有方案共享同一个隐含前提：**给定一段音频，想办法把它变成文字**。三轨调度、可预取性、覆盖率图、置信度门控、LLM 偏置、高后果位闭环——全都是在优化「识别」这一件事。它们把天花板锁死在：

- 字准约 91%（CER 8–9%），专名正确率可能只有 2/11；
- 全部音频都要跑一次模型；
- 延迟受自回归解码与发射策略约束；
- 「右上下文」要靠前瞻预算去换，且换来的仍只是几秒。

**但系统级字幕面对的绝大多数内容，文字本来就已经存在**：字幕文件、讲稿、歌词、论文与讲义、新闻稿、剧本、PPT、往期用户转写、被反复引用的原句。作者写下的文本，准确率天然是 100%，而且带正确的专名、数字、术语。

所以真正的突破口不是把 ASR 做得更准，而是：

> **把 ASR 从「作者」降为「兜底与时钟」。系统先取得已有文本，音频只用来把它贴回时间轴。**

### 天花板重估（对可检索到文本的内容）

| 维度 | 识别范式（前四轮上限） | 检索/对齐范式 | 变化来源 |
| --- | --- | --- | --- |
| 整体字准 | 约 91% | 接近 100% | 文本由作者写定，非模型生成 |
| 专名正确率 | 2/11 ~ 10/11 | 接近全对 | 专名直接来自原文，不经过声学解码 |
| ASR 调用量 | 100% 音频 | 趋近 0（仅缺口） | 识别变成兜底动作 |
| 右上下文 | 靠前瞻预算换几秒 | 天然全片无限 | 全文在识别前就到位 |
| 端到端延迟 | 解码窗口 + 发射策略 | 趋近对齐耗时（可并行） | 从自回归生成换成并行匹配 |
| 边际成本 | 每段内容都要算一次 | 一次命中可复用 | 指纹索引可共享 |

**唯一命门是检索覆盖率**：多少比例的内容能取回文本。这个数字目前未知，且是第五节的第一个实验要测的东西。覆盖不到的部分，前四轮的全部成果依然完整有效——新范式是加在上层，不是替换。

## 二、范式级突破口

### N1 · 音频即查询键（Audio-as-Query）

**一句话**：不把音频送进 ASR，用音频指纹去检索「这个内容在世界上对应的一切文本」。

**机制**

1. 取 3–5 秒音频，生成抗噪指纹（landmark 式频谱峰值对，或神经音频 embedding）；
2. 以指纹为查询键，在本地索引 + 可选远端索引中检索**内容身份**，而不是检索字幕文件；
3. 命中身份后，汇聚该内容的一切文本形态：外挂字幕、平台 AI 字幕、讲稿/教案、歌词库、论文与幻灯片、新闻通稿、剧本、往期用户转写、社区高频引用原句；
4. 多份文本不一致时按来源等级与文本相似度仲裁，产出规范全文；
5. 用强制对齐（CTC / Montreal Forced Aligner / attention alignment）把全文贴到音频绝对时间轴，输出词级时间戳；
6. **ASR 只在检索失败或对齐出现连续空洞的区间兜底**。

**天花板**：热门点播、公开课、播客、歌词、带稿演讲这类内容，字准接近 100%，专名/数字/术语直接来自原文；ASR 调用量趋近 0；一次命中可跨用户复用，边际成本趋零；多语言字幕只是同一份文本的不同投影。

**为什么前四轮没想到**：L0 覆盖图把「有没有字幕」做成二值命中判断，且只在已知来源列表里查；从没把**音频内容本身**当跨模态检索键，也没把「任意形式的文本」纳入候选，更没把强制对齐当成主路径而非事后修补。

**最大风险**：检索覆盖率；版本差异（剪辑版/直播回放/翻唱）导致全文与音频不完全对应；对齐在长静音、音乐、多人重叠处会漂移；远端检索涉及隐私与版权，应本地优先、只上传指纹不上传音频。

**最小验证**：取 20 段中文点播视频，只用指纹检索公开字幕/讲稿，测三个数——命中率、命中后的对齐误差（词级 ±ms）、命中区间相对全片 ASR 的字准提升。这个实验不需要训练任何模型。

### N2 · 预测稿 + 对齐，而非识别（Draft-then-Align）

**一句话**：LLM 在播放前写「素材」，音频到达后只做并行匹配，不做自回归生成。

**机制**

1. 播放前用元数据、同系列历史、章节大纲、讲者既往稿、PPT/讲义，让 LLM 生成一份**预测稿**。它是素材，不是字幕，允许错、允许缺、允许顺序不同；
2. 音频到达后，轻量 ASR 不逐词输出正文，只产**少量高置信时间锚点**（锚点词 + 绝对时间戳）；
3. 以锚点为约束，把预测稿并行对齐到时间轴；对齐不上的片段才退回常规 ASR；
4. 对齐置信度低于阈值时整段降级，预测稿永不直接呈现。

**天花板**：延迟从「解码窗口 + 发射策略」压到「对齐一次前向」，对可预取音源可做到零感知；**右上下文天然无限**——前四轮用前瞻预算 Δ 反复去换的东西，这里在识别前就免费拿到。更关键的是它改变了 LLM 的角色：前四轮一直在争「LLM 放纠错还是放偏置」，这里的答案是**让它写素材、不让它写结果**，写错了过不了对齐验证，因此无幻觉风险。

**为什么前四轮没想到**：始终把「生成」和「呈现」绑在一起，默认 LLM 的输出要么进字幕、要么进 prompt。从没设想过一份**永远不直接给用户看**的 LLM 产物，也没想过把 Whisper 从「作者」降成「时钟」。

**最大风险**：预测稿与真实内容偏离过大时对齐会整体失配（需要可靠的门禁判断何时退回 ASR）；即兴内容（直播闲聊、访谈）几乎无可预测结构；多份候选稿的对齐搜索成本。

**最小验证**：找 10 段有公开讲稿的演讲，只用讲稿 + 少量锚点词做对齐，测「完全不跑 ASR 正文解码」时的词级对齐误差与端到端延迟上界。

## 三、证据级突破口：给系统一个独立于模型的真相来源

前四轮所有纠错信号的共同缺陷是**都来自模型自评**：置信度、N-best 分歧、跨引擎一致性、LLM 语言先验。它们无法可靠发现「高置信度错」和「错字本身是合法中文词」（姚顺雨→尧舜禹）。N3/N4 换一类信号：**由作者写死、根本不经过模型的外部证据**。

### N3 · 音画互证（Cross-modal Evidence）

**机制**：系统级字幕往往同时能拿到画面（屏幕录制、播放器窗口、媒体流视频轨）。画面里天然有 PPT 文字、人名条、代码标识符、商品名、歌词、烧录字幕、网页标题、章节卡。用 OCR/VLM 按需读取这些帧，形成带时间戳的外部证据流，与音频输出做一致性校验：一致则锁定，冲突则按证据等级仲裁，**而「音画不一致」本身就是零参考检错信号**。

**天花板**：直接覆盖前四轮无解的两类错误；画面文字是作者写定的，专名、数字、代码、公式的准确率上限远高于任何声学模型；不依赖置信度、不需要第二个 ASR、不需要 LLM 改写。对课程、技术分享、产品发布、歌词 MV 这类「画面富含文字」的内容，收益可能比换引擎大一个量级。

**为什么前四轮没想到**：OCR 一直被归为「六类字幕来源之一」或「成本约为 ASR 20 倍、只能按需调用的兜底」，从没被当作**检错信号**；也没提出「不一致」本身可作为触发条件，而非替代文本。

**最大风险**：画面文字与口播不总对应（标题先出、口播后说；画面是举例而口播是概述），必须走证据等级与软仲裁，不能硬替换；OCR 需限定在锚点帧，否则成本失控；DRM 与屏幕录制权限限制。

**最小验证**：10 段技术演讲，只抽取含幻灯片文字的帧做 OCR，与 ASR 输出比对，统计「音画冲突位置中真错的比例」——若这个比例高，就证明不一致是比置信度更好的检错信号。

### N4 · 元数据优先解码（Metadata-first）

**机制**：不在「混音后的 PCM」上做文章，而是 hook 到应用**解码前的码流或网络请求**，先取得标题、章节、演职员、专辑/UP 主、分区标签、内嵌字幕轨、上传者自定义标签。这批元数据恰好是「高后果位」最可靠的来源：人名、作品名、术语、领域词表。在听到第一个字之前就建好实体表并注入解码约束。

**天花板**：把专名问题在源头消掉大半，而不是事后靠置信度门控或拼音候选去猜；同时拿到未压缩的原始单音轨与绝对时间基准，顺带解决混音污染与时间轴漂移。对 B 站这类场景，「标题 + UP 主 + 分区 + 标签」几乎就是一份现成术语表。

**为什么前四轮没想到**：HLS/DASH 分片抽取在方法学审查里被列为「音源层四级降级的第一级」，只被评价为「无损、可预取、免屏幕权限」，**从没被当成语义入口**。视角一直停留在「音频怎么拿到更干净」，没看到「随音频一起来的还有语义」。

**最大风险**：元数据可能缺失、错标或营销化；应用进程隔离与 DRM 限制；Web 页面结构多变导致适配器维护成本。

**最小验证**：对 20 段视频只取元数据建实体表，统计其中能覆盖实际出现专名的比例，并与无元数据基线比较专名错误率。

## 四、系统级突破口：把准确率从静态指标改成系统属性

### N5 · 个人化在线适配（越用越准）

**机制**：把每一次用户纠错变成训练信号，维护两样东西——**个人音素混淆矩阵**（记录「这台机器/这个说话人/这个频道，模型常把 X 听成 Y」）与轻量适配器（LoRA / 领域词典 / 解码偏置表）。解码时按混淆先验对易混位置做定向修正；同时保留全局基线，按说话人或频道分域生效，允许回滚。

**天花板**：把「一次性准确率」变成**收敛曲线**。第 100 次使用的字幕质量不再等于第 1 次——这是前四轮所有静态方案都不具备的属性。而且它绕开了置信度：修正依据来自**已确认的历史错误统计**，不是模型当下的自评。对固定 UP 主、固定课程、固定会议成员这类重复场景，长期收益可能远超一次性换模型。

**为什么前四轮没想到**：「用户纠错闭环」从第一版设计就有，但只做到「回灌词表」，没有在线适配、没有混淆统计、没有把「错误率随使用时长下降」定义成系统指标。

**最大风险**：过拟合到少数说话人；错误反馈本身可能错；需要防漂移、分域隔离与一键回滚；本地训练的资源与隐私边界。

### N6 · 字幕即收敛状态（Caption as Convergent State）

**机制**：每条字幕不是一条字符串，而是一个**带证据权重的候选集**。平台轨、检索轨、ASR 轨、画面轨、用户轨并发写入，各自附来源等级与证据；系统按证据权重持续收敛，已呈现的字幕可在阅读窗口内静默修正而不被察觉。可借鉴 CRDT 的思路：不要求写入顺序一致，只要求最终收敛。

**天花板**：**不再要求「一次给对」**，把不可逆错误变成可自愈。前四轮的 Volatile/Stable/Corrected 是单向锁定（稳定后不回改，就是怕抖动）；收敛模型则允许持续变好，只要修正发生在用户尚未读完的时间窗内。这让 N1/N3/N4 这些「晚到的高质量证据」可以放心接入，不必挤在首次呈现前全部到位。

**最大风险**：可见抖动与阅读体验；需要设计静默修正窗口、视觉过渡与「已读」判定；多轨证据权重需要标定。

### N7 · CaptionStream：把字幕做成操作系统能力

**机制**：把字幕从「AI 功能」升级为「**OS 级文本总线**」。应用发布结构化的 `CaptionStream`（文本 + 绝对时间戳 + 语言 + 证据等级 + 版本），系统统一渲染、统一切换、统一无障碍出口，类似 Now Playing / MediaMetadata 的扩展。XNook 做第一个客户端与参考实现。

**天花板**：**零算力、逐字准确、零延迟**，因为文本是作者写进去的。这是唯一能把用户最初那句「确保字幕的准确性」做到字面意义的路径，也是唯一真正配得上「系统级」三个字的方案。它同时消灭了权限、DRM 捕获、混音污染、算力、功耗这一整串工程问题。

**为什么前四轮没想到**：一直把「系统级」理解为「系统音频捕获」，即绕到 OS 底下拿声音；从没想过系统级也可以是「让应用把文本交出来」。前者是绕过应用，后者是与应用协作。

**最大风险**：生态采纳是长期工程，短期只能覆盖愿意接入或可 hook 的应用。但可渐进：先对可控应用实现适配器 → 抽象成协议 → 再推标准。即使只有少数应用接入，N7 的命中区间也是最廉价的高质量区间。

## 五、组合后的系统草图

七个方向不是互斥选项，可以按「证据质量从高到低」串成一条降级链。每一级拿不到证据才落到下一级，前四轮的全部成果集中在最后一级：

```text
音源出现
  │
  ├─ N7 CaptionStream：应用直接交出文本          → 零算力、逐字准确
  │      未接入 ↓
  ├─ N4 元数据：先建实体表与高后果位清单        → 识别前的语义入口
  │
  ├─ N1 音频指纹 → 检索已有全文                → 命中即接近 100%
  │      未命中 ↓
  ├─ N2 预测稿 + 锚点对齐（LLM 写素材不写结果）  → 并行匹配，无自回归延迟
  │      对齐失配 ↓
  ├─ 前四轮主链路：L0 覆盖图 → 缺口流式识别
  │      → SimulStreaming/AlignAtt → 三态合成
  │
  ├─ N3 音画互证：外部证据校验与零参考检错      → 修掉高置信度错与合法词错
  ├─ N5 个人混淆矩阵：按历史错误统计定向修正    → 越用越准
  └─ N6 收敛状态：多轨证据并发写入，阅读窗内静默修正
```

**关键结构性变化**：前四轮是「一条识别流水线 + 若干补丁」；这里是「一条**证据优先级链** + 一条识别兜底支路」。补丁不再挂在 ASR 后面，而是与 ASR 并列、按证据等级竞争输出权。N6 正是让这种竞争成立的基础设施。

**与专利草稿的关系**：草稿保护的是「应用无关 + 可预取性 + 双前沿差 + 多轨仲裁」的调度组合。新范式不改变这个内核，反而给它多添了几条候选轨（检索轨、预测轨、画面轨），**多轨仲裁的价值随轨数增加而上升**。可预取性判定也仍然决定 N1/N2 能否在播放前跑完。因此是加层，不是推翻。

## 六、最便宜的三个证伪实验（按成本排序）

大胆的想法必须配便宜的证伪，否则就是空想。三个实验都不需要训练模型：

| 顺序 | 实验 | 只测一个数 | 若结果不成立 |
| --- | --- | --- | --- |
| E1 | 20 段中文点播，只用音频指纹检索公开字幕/讲稿 | **检索命中率** | 命中率过低 → N1/N2 整体不成立，回到前四轮主链路；这是整轮想法的命门 |
| E2 | 10 段技术演讲，抽含文字的帧做 OCR，与 ASR 输出比对 | **音画冲突位置中真错的比例** | 比例低 → N3 的「不一致即检错信号」不成立，OCR 只能退回当字幕来源 |
| E3 | 10 段有公开讲稿的演讲，只用讲稿 + 少量锚点词对齐，不跑正文解码 | **词级对齐误差 + 端到端延迟上界** | 误差大或对齐不稳 → N2 的「LLM 写素材」路线不成立 |

**E1 是第一个要做的**：整个新范式的天花板都乘以「检索覆盖率」这个系数。覆盖率若只有 20%，它对整体体验的贡献就有限；若有 70–80%，那前四轮花在「把 ASR 从 91% 提到 93%」上的力气，价值远不如把检索做扎实。这个数目前完全未知，且一天之内就能测出来。

## 七、现实校验清单（本轮刻意跳过，列为下一步）

按用户要求，本轮**没有**做任何新颖性检索或否定性判断。若后续要把其中某个方向写成专利或论文，需要补的部分明确列在下面，但**这些核查不影响本轮思路在工程上是否成立**：

1. 单独核查 N1（音频指纹 → 全文检索 → 强制对齐）、N2（预测稿对齐）、N3（音画不一致检错）、N5（在线混淆适配）、N6（多轨收敛）的在先公开；
2. 核查 N7 是否已有平台级/OS 级字幕文本总线标准或类似提案；
3. 音频指纹检索、强制对齐、OCR/VLM 读屏、CRC/CRDT 收敛，都是成熟组件——**组件成熟是利好**，意味着 N1–N7 的落地风险主要在系统集成，不在算法可行性；
4. 前三轮已查明 Myna Player（2026-08-02）与多件双引擎专利覆盖了窗口缓存、指纹重锚、双前沿调度等；新范式把它们作为**兜底支路**保留即可，不必重新规避；
5. `docs/` 下技术草稿的披露风险不变，正式提交前不要推送公开仓库。

## 八、局限（不以「不可能」的语气写，只是待验证）

- 天花板表格是**机理推导**：「文本由作者写定 → 接近 100%」成立的前提是取回的全文与当前音频确实是同一版本，剪辑、翻唱、直播回放会破坏它；
- 检索覆盖率、对齐精度、音画冲突的真错率，三个关键数字**全部未知**，第六节的实验就是为了把它们测出来；
- 对纯即兴内容（直播闲聊、无稿访谈、语音通话），N1/N2/N7 都难以命中，前四轮的流式主链路仍是唯一解——新范式不是通用替代，是**按内容类型分派**；
- N5/N6 涉及长期状态，需要防漂移、可回滚、可解释，工程复杂度高于前四轮的静态流水线；
- N7 的生态采纳不受本项目单方控制；
- 本机 M3 Max / 36 GB 未做任何实测；本文所有数字为外部公开数据量级或推导；
- 本文不构成新颖性、创造性、侵权、自由实施或专利有效性的法律结论。

## 九、一句话收尾

**前四轮在问「怎么把音频认得更准」；这一轮的答案是「大多数时候不必认」。** 把作者已经写好的文本取回来、用音频把它对齐到时间轴，ASR 退到检索失败的缺口里——这是目前唯一能把字准从 91% 抬到接近 100%、同时把算力和延迟一起降下来的路径。

若要看它是否值得投入，先花一天做 E1：测检索命中率。一个数字就能决定整条路线。

> 附：这类「换问题定义 + 一个小而硬的评测」的工作，比继续调发射策略或换引擎更接近可发表的研究形态；若将来要往这个方向做，E1–E3 的评测集可以直接作为起步素材。

## 十、验证结构：不是七选一（方法论补正）

> 本节回应「接下来是不是要检测这七个组合哪个更好」。**答案是否**——若问的是七个排个名次选一个；**答案是是**——若问的是七个串成链后验证整链相对基线提升多少，但那属于前后对比，不是七选一。

### 10.1 为什么横向排名会得出误导性结论

1. **N7 / N4 / N1 / N2 是串联降级链，命中即短路**。N1 命中时 N2 根本不会运行，比较「N1 vs N2 谁更好」没有意义。各级收益是「该级覆盖率 × 该级质量」，不是并列可加的分数。
2. **N3 / N5 / N6 是横切层**，叠加在任何一级之上，本身不产生字幕来源，只改善已产生字幕的质量，没有独立的「字幕准确率」可报。
3. **指标不在同一根 y 轴上**：N1 命中率与对齐误差、N2 延迟上界、N3 检错精确率、N5 收敛斜率、N6 抖动/回退率、N7 接入覆盖率。硬凑总分会重演第三节那个坑——用整体 CER 排序，把专名 2/11 与 10/11 的差距抹平成 8.5% vs 8.6%。

### 10.2 三类比较，各管一件事

| 类型 | 回答什么 | 用在哪 |
| --- | --- | --- |
| **门控证伪** | 这个方向值不值得继续投入 | N1 / N2 / N3 / N4 / N7 |
| **横向 A/B** | 同一位置上哪个实现更好 | 兜底支路的引擎选型、`frame_threshold` 参数、强制对齐器选型 |
| **前后对比** | 整条证据链相对基线提升多少 | 最终验收（新链 vs 前四轮主链路） |

**唯一需要「哪个更好」式横向对比的，是兜底支路**：Whisper large-v3-turbo vs 中文优化引擎 vs 两者分歧仲裁，判据是高后果位错误率而非整体 CER。其余全是「过 / 不过」的门。

### 10.3 G0 前置：分层评测集（最容易被跳过、最致命）

新范式的收益集中在「有现存文本」层。若用混合素材算平均，提升会被稀释到看不见，容易被误判成「没什么用」。评测集必须按内容类型分层，且**按层报结果，不报加权总分**：

- 有现存文本（点播、公开课、播客、带稿演讲）
- 有可预测结构但无文本（同系列、有大纲/PPT）
- 即兴内容（直播闲聊、无稿访谈、语音通话）
- 画面富文字（技术分享、产品发布、歌词 MV）
- 专名密集（人名、地名、术语、数值集中）

统一五个指标：整体 CER · **高后果位错误率** · 零推理区间占比 · 端到端呈现延迟 · 变差句数。

### 10.4 门控表：每道门只测一个数

| 门 | 只测一个数 | 不通过时的动作 |
| --- | --- | --- |
| G1 | 音频指纹检索命中率（E1） | N1/N2 停止投入，回前四轮主链路 |
| G2 | 命中区间的词级对齐误差（E3 前半） | 强制对齐不进主链路，取回文本只作参考 |
| G3 | 未命中区间用预测稿对齐的可行性（E3 后半） | N2 降级为纯偏置词来源 |
| G4 | 音画冲突位置中真错的比例（E2） | OCR 只当字幕来源，不当检错信号 |
| G5 | 兜底支路各引擎的高后果位错误率 | 选定引擎与 `frame_threshold` |
| G6 | 长期收敛斜率与抖动率 | N5/N6 延后或不做（需时间跨度，最后做） |

**顺序**：G0 → G1 → G2 → G3 → G4 → G5 → 前后对比 → G6。G1 未通过前不要启动 G6 的长期实验。

### 10.5 前后对比怎么做

- **基线**：前四轮主链路 = L0 覆盖图 → 缺口流式识别（SimulStreaming/AlignAtt）→ 三态合成；
- **实验**：第五节的证据优先级链；
- **条件**：同一份分层评测集、同一台机器、同一套五个指标；
- **报告方式**：逐层给出「基线 / 实验 / 差值」，**特别单独列出「有现存文本」层**，因为整条链的价值主要产生在那里；即兴内容层预计与基线持平，这不是缺陷而是设计预期。

### 10.6 三个不要

1. 不要给七个方法打总分排名；
2. 不要用整体 CER 作唯一判据（会把专名收益抹平）；
3. 不要在 G1 未通过前投入 N5/N6 的长期实验或 N7 的生态工作——那是最贵的部分，却依赖最便宜的那个数。

## 十一、实时性审视：七层会不会拖慢响应、导致无法实时

> 本节回应用户质疑「七个连在一起会不会过于冗杂、响应时间变长、无法实时」。**结论：若按字面串成同步流水线，一定会崩；但正确实现下关键路径不随层数增长。** 延迟可以做到不增加，**工程复杂度确实会增加**——两者必须分开说。

### 11.1 延迟预算

字幕相对音频的偏移，行业端到端目标约 400–500 ms，超过 1 s 即被明显感知。对不可预取音源，音频到达后只有这几百毫秒可用；对可预取音源，播放前可以任意计算，播放时纯读取，延迟≈0。

### 11.2 逐层归属（只有两层真正站在关键路径上）

| 层 | 位置 | 关键路径耗时 | 超时降级 |
| --- | --- | --- | --- |
| N7 文本总线 | 快路径查表 | 约 0 ms | 无 |
| N4 元数据 | 会话级取一次，之后查表 | 0 | 空实体表 |
| N5 混淆矩阵 | 解码时查表 | 约 0 ms | 跳过 |
| N6 收敛状态 | 数据结构层 | 常数级 | 退化为单轨 |
| **N1 指纹检索** | 可预取→播放前；不可预取→异步旁路 | 0 / 不等 | 走流式兜底 |
| **N2 预测稿** | LLM 生成在播放前；增量对齐在快路径 | 对齐约 20–50 ms | 退回常规 ASR |
| N3 画面证据 | 异步旁路，按需抽帧 | 0（不阻塞） | 丢弃本帧证据 |
| 兜底流式 ASR | 快路径，仅未命中时 | 约 180–300 ms | — |

**关键路径合计**：

- 可预取且命中：查表 + 渲染，**< 20 ms**；
- 可预取未命中但播放前跑完：同上；
- 不可预取：链路塌缩为流式 ASR，**约 200–300 ms，与层数无关**；
- 最坏（强行同步等指纹/OCR/LLM）：**> 1 s，实时失效**。

> 上表耗时为公开数据量级与机理推导（流式 ASR 约 180–300 ms 来自 SimulStreaming 社区实测，增量对齐 20–50 ms 为并行前向的量级估计），**本机 M3 Max 未实测**。

### 11.3 三种会让实时性失效的写法（明令禁止）

1. **等 3–5 秒音频攒够再做指纹检索** —— 光这一步就是 3–5 s。改为：可预取音源在播放前算完；不可预取音源用 0.5–1 s 短指纹粗召回 + 后台异步精查，或直接跳过 N1。
2. **同步等待 OCR/VLM 或 LLM 生成** —— 几百毫秒到几秒。一律异步，结果只影响后续区间。
3. **多轨仲裁等「所有轨都到齐」** —— 等价于等最慢的一轨。改为 deadline 驱动：到点就用手头最好的候选渲染，晚到的证据走 N6 静默修正。

### 11.4 三条硬约束

- **首帧 deadline**：`t_deadline = t_audio + L_budget`（建议 300 ms，可配）。任何层超时即降级，绝不阻塞呈现；宁可先显示流式 ASR 的低质量候选，也不等高质量证据。
- **可预取性剪枝**：链路长度按音源动态变化。可预取时慢路径整体前移到播放前；不可预取时 **N1 / N2 / N7 自动剪掉**，链路塌缩为「N4 会话级实体表 + 流式兜底 + 异步 N3/N6」。前四轮的可预取性判定在这里正好充当天然剪枝器——它不是只用来调度前瞻预算，还用来决定「这条链到底有几层」。
- **统一证据契约**：每层实现同一接口（优先级、deadline、超时动作、证据等级、是否允许异步、写入的时间区间），调度器按 deadline 取当前最优候选。这样新增一层的复杂度是线性的，而不是与其他层两两交互的平方级。

### 11.5 复杂度的真实代价（不粉饰）

延迟可以做到不增加，但下列代价**省不掉**：多轨状态与缓存一致性、异步结果的乱序写入、静默修正的视觉过渡与「已读」判定、七套适配器的维护、以及超时降级路径的测试覆盖。真正的风险从「算得慢」转移到「**状态一致性与可见抖动**」，这类缺陷比延迟更难复现和定位。

内存不是瓶颈：字幕是文本，10 分钟内容仅几 KB，多轨候选集同样极小；真正的资源压力在慢路径的模型常驻与并发，而它们都在播放前或空闲时运行。

### 11.6 最小可行版本：三层起步，不要一次上七层

| 保留 | 理由 |
| --- | --- |
| N4 元数据 | 会话级一次，零延迟，且是 N1 检索的查询线索 |
| N1 指纹检索 | **仅可预取音源、仅在播放前**，命中区间零推理 |
| 兜底流式 ASR | 不可预取与检索失败时的唯一解 |
| deadline 调度器 | 先把「超时即降级」机制跑通，这是后续所有异步层的地基 |

链路只有三个分支，可先回答一个前置问题：**新链是否不比基线慢**。确认后再依次加 N2（预测稿）、N3（异步画面证据）、N6（收敛状态）、N5（长期适配）、N7（生态接入）。每加一层都重测一次端到端延迟与变差句数。

### 11.7 对第十节验证结构的补正

在 G0 与 G1 之间插入一道**延迟门 G0.5**：在三层起步版本上测端到端呈现延迟，与「前四轮主链路」基线对比。若新链延迟显著高于基线，说明 deadline 或剪枝实现有误，应先修复再继续 G1。这道门不需要模型训练，且能防止「为了准确率把实时性做没了」——这正是用户质疑的核心风险。

### 11.8 需要实测的量

- 增量对齐在本机 M3 Max / 36 GB 上的实际耗时（11.2 中 20–50 ms 为量级估计）；
- 短指纹（0.5–1 s）粗召回的命中率相对 3–5 s 指纹的下降幅度；
- 异步证据的平均晚到时长，以及它落在「可静默修正阅读窗」内的比例；
- 多轨常驻时的峰值内存、功耗与风扇表现；
- `L_budget` 取 200 / 300 / 500 ms 时的「降级触发率」与用户可感抖动。
