# X Nook v1.5.0

发布日期：2026-11-25

基线：v1.4.6（`21fb09b`）

这是 1.4.6 全量审计后的修复中版本。它不新增功能，重点是把已经确认的稳定性、能耗、隐私和工程问题一次收口，并让“没有歌曲在播放”时的状态回归干净、静态的 41pt 胶囊。

## 为什么发这个中版本

1.4.6 的全量检测（报告：`docs/verification/2026-11-25-1.4.6-full-audit.md`）确认了 1 个可复现崩溃、2 个 P1 级体验问题和一组 P2/P3 问题：

- 实时字幕在负时间戳/迟到 OCR 输入下触发 `Range` 运行时崩溃；
- 暂停后最后一行字幕仍滚动，胶囊维持 60pt，空闲 CPU 偏高；
- 面板 `overviewPage` 的多个兄弟视图被 `ZStack` 叠在同一坐标；
- `caption.log` 无限增长且保存完整转写正文；
- ScreenCaptureKit 每秒丢帧、MediaRemote 注册持续产生错误日志；
- 每 50 秒重建 `SFSpeechRecognizer`；
- 两个字幕 Provider 存在 Swift 6 actor 隔离警告；
- 应用数据分散在 `XNook` 与 `X Nook` 两个目录。

v1.5.0 按 P0→P1→P2→P3 顺序修复上述问题，并把“无歌曲/停止播放”场景作为发布前必测项。

## 修复明细

### 1. P0：字幕调度器崩溃

**现象**：实时字幕运行中，时间轴重建或 OCR 迟到时，`CaptionScheduler.coverageRatio` 用倒置端点构造 `Range`，触发：

```text
Swift runtime failure: Range requires lowerBound <= upperBound
```

**修法**：

- 候选先与目标区间求交，再校验 `lower.isFinite`、`upper.isFinite`、`lower < upper`；空区间、倒置区间、NaN 全部 `continue`，不进入 `Range`。
- `FrameTextEvidenceProvider` 新增 `sessionEpoch`：`start/stop/reset` 递增，重置时清空 `inFlight`；抓帧时捕获 `epoch` 与 `clock.generation`，完成时先验 epoch 再验 generation。
- 时间轴重置前抓到的迟到 OCR 结果整体丢弃，不再用新时间轴解释旧画面。

**回归**：`CaptionSchedulerTests` 20/20，新增负时间戳候选与 freshness 断言。

### 2. P1：暂停后的滚动字幕与空闲功耗

**现象**：音乐暂停后，最后一行字幕继续横向滚动，胶囊保持 60pt；旧实例播放中 CPU 21.8%。

**修法**：

- `CaptionScheduler` 记录 `lastEvidenceHost`，用宿主时钟判断“最近是否还有新证据”，不受暂停冻结的源时间轴影响。
- `CaptionManager` 以 60ms tick 维护 `lineIsFresh`（8 秒窗口），让 SwiftUI 在暂停后主动把“仍在出字幕”降为 false。
- `NotchContentView.isTickerLive` 增加暂停硬门控：`isPlaybackPaused == true` 时直接停止 Ticker；播放中/等待源保持活跃；其余情况才看 `lineIsFresh`。
- `MarqueeText` 改为 30fps `TimelineView`；25pt/s 的滚动速度下肉眼无差别，但不再按 ProMotion 120fps 重建整行文本。

**真机结果**：

| 场景 | 旧 1.4.6 | v1.5.0 |
|---|---|---|
| 播放中 CPU | 21.8% | 8.2% |
| 暂停后 `MarqueeText` 采样 | 4 条 | 0 条 |
| 暂停后 `TimelineView` 采样 | 27 条 | 7 条 |
| Music 停止、无歌曲 | 残留歌词/滚动 | 胶囊 271×41，无歌词、无均衡器 |
| 无歌曲空闲 CPU | 约 15.5%（旧实例） | 3.3% |

**产品语义**：播放中按暂停时，最后一行字幕静态定格、胶囊保持 60pt，不再滚动；完全停止/无歌曲时回到 41pt。这延续了 1.4.6 “暂停后冻结字幕时间轴”的设计，不是残留 bug。

### 3. P1：自适应面板多视图叠放

**现象**：隐藏任务模块后，默认开启的待办入口会压住第一个组件；布局异常提示也会和内容重叠。

**修法**：

- `ExpandedPanelView.overviewPage` 的配置分支和回退分支都收进单一 `VStack`，显式规定“错误提示/恢复入口 → 组件网格 → 待办入口”的顺序。
- 概览内容固定宽度 `panelWidth - outerPadding*2`。
- 外层 `ScrollView` 使用 `.scrollIndicators(.never)`，避免传统 scroller 占 17pt 宽度导致正文反复重排。
- 测量宽度改用契约值 `panelWidth`，不再依赖滚动条挤压后的实际宽度。

**回归**：`AdaptiveWorkflowPreviewTests` 16/16；`TaskInboxShortcutVisibilityTests` 通过；渲染全量 1353 项、8 跳过、0 失败。

### 4. P2：字幕日志轮转与隐私

**修法**：

- 单文件上限 2MB，保留 `.1`、`.2` 两份；最旧的一份自动删除。
- 日志目录 `0700`，当前日志和轮转备份统一 `0600`。
- 转写正文默认只记录 `chars=N` 与 `end=...`；排障时可显式开启：

```bash
defaults write com.meteorkid.xnook captionLogTranscripts -bool YES
```

- `pretranscript` 心跳降噪：无文件时 5 分钟一条，有文件时 30 秒一条，不再每 10 秒刷 `tick file=nil`。

**实测**：旧 4.96MB、约 7.3 万行日志在启动时轮转为 `caption.log.1`；新 `caption.log` 12KB/0600，中文转写正文 0 条。

### 5. P2：ScreenCaptureKit 丢帧与 MediaRemote 日志

**修法**：

- `SystemAudioTap` 同时挂 `.audio` 和 `.screen` 输出。SCK 即使不消费画面也会生成视频帧；只挂 audio 输出时帧会被系统每秒丢弃并写 `stream output NOT found`。
- 新增的 2×2、1fps screen 输出在 handler 第一行按类型丢弃，不产生解码或内存负担。
- `MediaManager` 在 Perl 桥可用时跳过本进程的 MediaRemote 通知注册；信息轮询从 1 秒放宽到 2 秒，减少每天约 8.6 万次 Perl 进程唤醒。

**实测**：修复构建 0 条 `stream output NOT found`、0 条 `MRMediaRemoteGetNowPlayingInfo Code=35`；旧实例同窗口残留约 246 条丢帧、174 条 MediaRemote 错误（含旧进程日志）。

### 6. P3：语音识别器复用与并发警告

- `SpeechEvidenceProvider` 按 locale 缓存 `SFSpeechRecognizer`；50 秒换会话只重建 request/task，`stop` 时清空缓存。此前 8 天累计创建 4,894 次，`leaks` 中留下 124 个相关节点。
- `FrameTextEvidenceProvider`、`PreTranscriptProvider` 的协议一致性改为 `@preconcurrency CaptionEvidenceProvider`；重新编译后 0 条 `ConformanceIsolation` 警告。

### 7. P3：数据目录统一与授权迁移

- `FileLicenseStore` 默认目录由 `Application Support/X Nook` 改为 `Application Support/XNook`。
- `LicenseManager` 启动前把旧 `X Nook/License/session.json`、`device.json` 复制到新目录；旧目录保留，作为回退。
- `LicenseDataExport` 排除 `License` 与 `.state`，授权凭据与试用锚点不再进入导出包。
- 实测修复构建启动后生成 `~/Library/Application Support/XNook/License/session.json`，应用保持已激活。

## 行为变化与升级说明

1. **授权不重置**：签名身份沿用 `XNook Local Signing`，升级后无需重新激活；首次启动仍可能弹一次钥匙串“始终允许”（与 1.3.34 起的行为一致）。
2. **数据目录**：授权记录迁移到 `Application Support/XNook`；旧 `X Nook/License` 不删除，确认无误后可手动清理。
3. **日志**：默认不再保存转写原文；如需排障，显式打开 `captionLogTranscripts`。旧日志会在启动时按 2MB 轮转。
4. **媒体状态**：没有歌曲/播放器停止时，胶囊回到 41pt，不显示歌词或均衡器；播放中暂停时保留最后一行静态字幕。
5. **导出包**：数据导出不再包含 `License` 与 `.state`，这是有意的隐私边界变化。

## 已知边界

- 播放中暂停后最后一行静态保留 60pt，是当前明确的产品选择；如果后续要求“暂停即回到 41pt”，需要单独改 UI 语义，不影响本版发布。
- 媒体可视化只在 `isPlaying` 为 true 时动画；无歌曲停止场景已验证为 0 个 `TimelineView`。若其他播放器错误上报 `isPlaying`，仍可能出现动画，需要按具体来源排查。
