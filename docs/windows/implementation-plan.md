# Windows XNook 实施计划

日期：2026-10-17。用户已授权按前一轮评估实施 Windows 客户端，并要求保留与 XIsland 的双向切换；已选择本地 .ics 日历。

## 设计与边界

保留 SwiftUI/AppKit macOS 客户端，新增 windows/ Tauri 2 + Rust + TypeScript 工程。优先复用自有 XIsland 的窗口策略；媒体改接 Windows GSMTC，日历使用本地 ICS，笔记/任务/文件引用使用版本化本地 JSON。界面继承黑色药丸、工具概览和详情结构。首次启动不填充伪造数据，浏览器开发预览须明确标记。

两个 Windows 应用使用独立安装包和同一版本的本机联动协议，限定 XNook/XIsland 身份。切换请求必须有确认和超时：目标已显示才让源窗口隐藏；失败不丢窗口。启动和全屏恢复不得夺回已转交的显示权。提供按钮与横向滚动手势入口。为支持冷启动，在用户目录记录各应用的注册信息。

不将 macOS 的安全书签和 EventKit 事件 ID 当成 Windows 可用引用。现有 Mac 版本不参与 Windows 联动。XIsland 0.1.3 旧包不支持新协议，须同时提供包含联动改动的新测试包。

## 执行顺序

1. 基线：冻结现有源码哈希，约定前后端命令和联动协议。
2. 并行实现：原生系统接入；界面与领域模型；双应用联动及 XIsland 配套改动。
3. 集成：核对所有命令、持久化、拖放、歌词、日历和联动错误路径。
4. 验证：前端类型/行为/构建；Rust 单元与独立进程联动；浏览器真实交互；Windows 目标编译。
5. 交付：两端安装测试包、哈希清单、操作及验收说明；保存 Obsidian 总结。

## 必须覆盖的回归

- 笔记保存失败保留草稿；存储损坏不覆盖原件；删除撤销；导出原文。
- 任务结束/恢复和历史中的文件快照不依赖文件架仍存在。
- ICS 时区、全天、多日、重复事件与取消记录；不支持项明确提示。
- 媒体切歌、暂停、进度跳转与过期歌词请求不覆盖新曲目。
- 双应用同时启动、往返切换、目标缺失/退出/超时；全屏恢复不能让隐藏应用重新抢位。
- 非 Windows 主机明确标记媒体能力不可用，不伪装真实播放。
