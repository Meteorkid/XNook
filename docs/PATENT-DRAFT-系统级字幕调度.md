## 〇、发明点确定与规避设计论证（内部工作稿，不属于申请文件）

### 0.1 必须放弃的原始主张

`docs/LIVE-CAPTION-DESIGN.md` 的核心主张是「识别进度与播放进度解耦，提前识别以兼顾准确与实时」。该主张已被 Myna Player（2026-08-02 公开，GPL-3.0-or-later）完整公开，且其公开日早于本申请的拟申请日。同时，「离线转写整段媒体生成带时间戳字幕」（`CN109246472A`）、「提前批量处理媒体内容」（`US9305552B2`）、「延迟播放补偿识别耗时」（`US9305552B2`、`CN115643424A`）也均为现有技术。

**因此该主张只能作为最接近的现有技术写入背景技术，不能作为发明点。**

### 0.2 收窄后的发明点

拟申请主题：**一种应用无关的、以音源可预取性和双前沿差为控制量的字幕调度方法**。

其区别于全部检索到的对比文件的一组必要技术特征为：

| 编号 | 必要技术特征 | 为什么必须写进独权 |

### 0.4 创造性论证思路（供代理师改写）

主张的协同关系：F1 使系统能区分可预取与不可预取音源；F3 依据 F2 实测的前沿差动态分配前瞻预算，使可预取音源在播放开始前即完成高精度转写、不可预取音源不被强加离线模型；F4 使二者在同一播放时钟下共享一条时间轴；F5/F6 使音源切换与跳转不破坏已完成的推理工作。四者共同产生「**在音源身份动态变化的应用无关环境下，重复推理次数与峰值内存占用同时下降**」的系统内部性能效果，该效果不是任一单独特征所能获得的。

**风险（必须向申请人如实说明）**：每一列均有对比文件覆盖，审查员很可能依据「已知手段的简单并列」提出创造性不足的意见。答复空间主要在于：现有技术的组合没有动机把「可预取性」作为跨音源的闭环控制量，且组合后产生了非预期的资源节省效果。若代理师判断该论证不成立，建议改走第十章的备选路线。

## 一、说明书摘要

本申请公开一种应用无关的字幕调度方法及装置，属语音识别与多媒体数据处理技术领域。经操作系统音频捕获接口取得当前音频及音源描述符，该描述符含进程标识、播放前沿、播放速率与后续音频可访问标志；据其计算可预取度；维护按绝对源时间戳统一索引的预取轨与流式轨，并据连续覆盖区间确定转写前沿；以转写前沿与播放前沿之差、可预取度、推理单元负载为闭环控制量，动态确定前瞻预算并在两轨间择一或切换；音源变化或播放跳变时保留已完成规范时间窗，以音频指纹重锚时间轴并仅补转写未覆盖区间；按绝对源时间戳选取已稳定条目输出。本申请可减少重复转写次数、峰值内存占用与音频缓冲数据量，提高推理单元利用率。

## 三、权利要求书

**1.** 一种应用无关的字幕调度方法，由包括本地推理单元与存储器的计算设备执行，其特征在于，所述方法包括：

通过操作系统提供的音频捕获接口获取当前播放的音频数据，并获取与所述音频数据对应的音源描述符，所述音源描述符至少包括产生所述音频数据的进程标识、播放时钟所指示的播放前沿 T_p、播放速率，以及用于指示所述播放前沿之后的音频数据能否在所述播放前沿到达之前被读取的可访问标志；

依据所述音源描述符计算可预取度 P，所述可预取度 P 至少由所述可访问标志、所述播放前沿之后可被提前读取的音频时长 L、以及是否已存在与所述音源描述符对应的带绝对源时间戳的候选字幕轨共同确定；

维护至少两条候选字幕轨，所述至少两条候选字幕轨均按所述绝对源时间戳索引，且包括由平台字幕接口或由非流式语音识别模型提前转写得到的预取轨、以及由流式语音识别模型得到的流式轨；并维护转写前沿 T_t，所述转写前沿 T_t 为所述至少两条候选字幕轨中自所述播放前沿 T_p 起连续覆盖的字幕条目所对应的最大绝对源时间戳；

计算前沿差 Δ = T_t − T_p，并依据由所述可预取度 P、所述前沿差 Δ 与本地推理单元负载 U 构成的三元组，通过闭环控制确定当前调度周期的前瞻预算 B 与工作轨，其中：当 P 不小于第一阈值且 Δ 小于下限阈值时，选择所述预取轨，从所述播放前沿之后的音频数据抽取时长为 B 的规范时间窗，由所述非流式语音识别模型转写后按所述绝对源时间戳写入所述规范时间窗；当 P 小于所述第一阈值时，选择所述流式轨，并将所述下限阈值设定为所述流式轨的稳态延迟值；当 Δ 大于上限阈值或 U 大于负载阈值时，降低所述前瞻预算 B 或暂停向所述预取轨写入，并释放相应的音频缓冲区；所述前瞻预算 B 随 Δ 的减小而增大，且 B 的上限由所述音频时长 L 与可用内存共同约束；

在检测到所述进程标识发生变化或所述播放前沿发生跳变时，保留已写入的规范时间窗，从当前音频数据提取音频指纹，在所述至少两条候选字幕轨中检索与所述音频指纹匹配的锚点，依据匹配到的锚点把跳变后的播放前沿重新映射到所述绝对源时间戳，并仅对未被所述规范时间窗覆盖的时间区间发起转写；以及

按所述绝对源时间戳，在覆盖同一时间区间的多条候选字幕轨条目中选取置信度最高且状态为已稳定的条目输出，且输出条目在候选字幕轨之间的切换边界被限定在已稳定条目的边界处。

## 四、说明书

### 4.1 技术领域

本申请涉及语音识别技术、多媒体数据处理技术与操作系统音频调度技术，尤其涉及一种在应用无关环境下、依据音源的可预取性对多条候选字幕轨进行调度的方法、装置、电子设备、存储介质及计算机程序产品。

### 4.2 背景技术

为任意正在播放的音频提供字幕，需要在不依赖具体应用配合的前提下取得音频数据，并在本地计算资源有限的条件下兼顾转写准确率与呈现时延。

已有公开方案分别解决了该问题的不同侧面：

其一，公开号为 `CN120071957A` 的申请提出从计算设备的音频混合器获得应用输出的音频数据，依据与音频数据关联的内容类型确定是否加字幕，从而在应用无关层面生成字幕，并可借助元数据避免对不适合加字幕的音频进行过度分析。

其二，公开号为 `CN116635932B` 的授权专利提出由主语音识别引擎与辅语音识别引擎并行接收同一音频流，分别采用较长与较短的先行缓冲器，把辅引擎的低延迟结果先附到词列表，再把主引擎的高准确率结果合并替换，并对属于类模型的词暂停拼接。

其三，公开号为 `US12254869B2` / `EP4200842B1` 的专利提出以可变前瞻上下文训练单一模型，在推理时依据查询对延迟的敏感度或用户的延迟容忍度设定不同长度的前瞻上下文，并可并行运行低延迟与高延迟两个解码分支。

其四，公开号为 `US10743085B2` 的专利提出围绕当前播放位置所在的时间索引范围，先查询标注缓存设施，命中则取用已有语音文本，未命中才执行自动语音转写。公开号为 `US9305552B2` 的专利提出把高准确率转写文本按锚点词对齐到自动语音识别输出的时间轴上，并通过缓冲或延迟媒体播放来补偿处理耗时。公开号为 `CN109246472A` 的申请提出从视频提取音频并离线转写为带时间戳的字幕文本。

其五，公开号为 `US10021445` 的专利提出在字幕文件内嵌音频指纹锚点，通过比对指纹计算时间戳差并传播到后续字幕条目以校正同步。公开号为 `CN202511057472` 的申请提出把直播流、点播文件与外接设备输出等多源音频统一转换为脉冲编码调制数据并存入容量可动态调整的缓存区，按语义重要性评分动态分配算力。

其六，2026 年 8 月公开的一个开源本地播放器项目提出在播放位置之前处理音频：把媒体划分为规范的互不重叠时间窗，按播放位置给待转写窗口排定优先级，以媒体指纹与管线配置键作为缓存身份，在跳转时以代次标识取消在途任务并保留已完成窗口，并按播放器原生时钟渲染字幕。该项目明确以本地媒体文件为输入，并指出监听系统音频对其场景并非合适抽象。

上述方案各自在其适用范围内有效，但在**音源身份可变化的应用无关环境**中仍存在以下技术问题：

1. **音源的可预取性未知导致策略错配**。已知方案或面向内容类型（音乐/电影/语音），或面向用户对延迟的容忍度，或隐含假定输入恒为可随机访问的本地文件。当同一系统在点播、直播、实时会议与本地文件之间切换时，若统一采用离线模型，会对不可预取的音源产生无法完成的前瞻等待、无效的音频缓冲与推理单元占用；若统一采用流式模型，则对可预取的音源白白放弃了本可获得的长上下文准确率。
2. **音源切换与播放跳变导致已有推理工作被丢弃**。已有缓存方案多以单条队列或单个媒体文件为边界，缺乏在多条候选轨之间重锚时间轴并复用已完成转写结果的机制，跳转后往往重新推理，造成重复计算与内存反复分配。
3. **多条候选轨的时间轴不一致导致输出回退**。当平台字幕、提前转写结果、流式结果同时存在时，若各轨以窗口相对时间而非统一的绝对源时间戳表示，切换瞬间容易出现文本回退或重复显示，且难以界定安全的切换边界。

### 4.3 发明内容

#### 4.3.1 要解决的技术问题

本申请要解决的技术问题是：在应用无关、音源身份可动态变化且本地推理单元与内存预算受限的计算设备上，如何使多条候选字幕轨的转写进度持续覆盖播放进度，同时避免对不可预取音源施加无效前瞻、避免音源切换与播放跳变引发的重复推理，并避免多轨切换时的时间轴回退。

#### 4.3.2 技术方案

为解决上述问题，本申请提供如权利要求 1 所述的方法，其要点如下（各步骤的细节见 4.5 节）：

1. 从操作系统音频捕获接口取得音频数据的同时取得音源描述符，其中除进程标识、播放前沿与播放速率外，还包含「播放前沿之后的音频数据能否在该前沿到达之前被读取」的可访问标志。该标志把音源区分为可预取与不可预取两类，是后续全部调度决策的输入。
2. 依据可访问标志、可提前读取的音频时长、以及是否已存在对应候选字幕轨计算可预取度 P。
3. 把平台字幕接口或提前转写得到的预取轨、以及流式识别得到的流式轨，统一按绝对源时间戳索引；并把转写前沿 T_t 定义为自播放前沿 T_p 起连续覆盖的字幕条目所对应的最大绝对源时间戳。由此把「是否跟得上播放」转化为一个可测的标量 Δ = T_t − T_p。
4. 以 (P, Δ, U) 三元组为闭环控制量确定前瞻预算 B 与工作轨：可预取且落后时提前抽取规范时间窗做非流式转写；不可预取时切到流式轨并以其稳态延迟设定下限；领先过多或负载过高时下调 B、释放缓冲区。B 的上限同时受可提前读取时长与可用内存约束。
5. 音源变化或播放跳变时不清空已完成窗口，而以音频指纹在多条候选轨中检索锚点，把新的播放前沿映射回绝对源时间戳，仅补转写未覆盖区间；在途任务以代次标识管理，迟到结果被丢弃。
6. 输出时在同一时间区间的多条候选条目中选取置信度最高且状态为已稳定的条目，并把轨间切换边界限定在已稳定条目的边界处。

#### 4.3.3 有益效果

与仅采用单一识别轨或仅面向单一音源的方案相比，本申请通过把可预取性与双前沿差引入调度闭环，可获得以下**计算机系统内部性能方面**的技术效果：

1. **减少重复转写次数**：音源切换与播放跳变时复用已写入的规范时间窗，仅补转写未覆盖区间，避免对同一音频区间重复调用语音识别模型。
2. **降低峰值内存占用与音频缓冲数据量**：前瞻预算 B 由 Δ 闭环调节并受可用内存约束，在 Δ 超过上限或负载过高时主动下调并释放缓冲区，避免为不可预取音源保留无效的长前瞻缓冲。
3. **提高本地推理单元利用率与降低功耗**：对不可预取音源不启动非流式模型，对可预取音源把推理工作移到播放前沿之前完成，使推理单元的占用在时间上更均匀，减少空闲与突发的交替。
4. **保证多轨输出的时间轴一致性**：各轨统一按绝对源时间戳索引，并把切换边界限定于已稳定条目，消除切换瞬间的文本回退与重复渲染带来的额外处理开销。

#### 4.5.3 可预取度计算与闭环调度

可预取度按 `P = w₁·A + w₂·min(L/(L_ref/r), 1) + w₃·C` 计算，其中 A∈{0,1} 为可访问标志，C∈{0,1} 表示是否已有以同一媒体指纹与管线配置键索引的候选轨，w₁+w₂+w₃=1。播放速率 r>1 时以 `L_ref/r` 作为归一化基准，因为倍速播放会压缩可用于提前转写的实际时间。

音频获取层级按以下顺序降级，且仅当生效层级为「从应用媒体流直接抽取音频基本流」时 A 取 1：媒体流抽取 → 标签页音频捕获接口 → 操作系统级音频回环 → 虚拟音频设备回环。其余层级下，系统只能获得已经输出到播放时钟处的音频，无法在播放前沿之前取得后续数据，故 A 取 0，L 取 0。

闭环调度每个周期执行：

```
输入: 音源描述符 D, 合并视图 M, 推理单元负载 U, 上一周期预算 B
 1  P   ← prefetchability(D)
 2  T_p ← D.playback_frontier
 3  T_t ← max_contiguous_covered_timestamp(M, T_p)
 4  Δ   ← T_t - T_p
 5  若 P ≥ P_th:
 6       Δ_min ← 预设下限
 7       工作轨 ← 预取轨
 8  否则:
 9       Δ_min ← 流式轨稳态延迟
10       工作轨 ← 流式轨
11  若 Δ < Δ_min:      B ← min(B + ΔB, min(L, mem_budget_to_duration()))
12  否则若 Δ > Δ_max: B ← max(B - ΔB, B_min); 释放超额音频缓冲区
13  否则:              B ← B
14  若 U > U_th:      B ← max(B - ΔB, B_min); 暂停向预取轨写入
15  依据工作轨与 B 生成规范时间窗任务，按 |k - floor(T_p/W)| 升序入队
16  返回 B, 工作轨
```

其中 `mem_budget_to_duration()` 把当前可用内存按音频采样率、位深与声道数换算为可缓冲的音频时长上限，使前瞻预算 B 同时受 L 与内存约束。步骤 11–14 与步骤 5–10 共同构成带滞回的闭环：Δ 用于调节投入的推理资源，P 用于决定投入哪种识别轨，二者不相互替代。

#### 4.5.4 跳变重锚与增量补转写

当 pid 变化，或 T_p 的相邻两次采样之差超出由播放速率归一化的跳变阈值时：

1. 在途转写任务的代次标识 `g` 自增，取消在途任务；已完成并写入的规范时间窗全部保留，不随代次失效。
2. 从当前捕获音频提取音频指纹，在媒体指纹库与各候选轨的锚点表中检索匹配锚点；匹配成功则得到该锚点的绝对源时间戳 `t_anchor` 与当前播放位置 `t_now` 之间的偏移 `δ`。
3. 把跳变后的播放前沿重新映射为 `T_p' = t_anchor + δ`，据此在合并视图上重新计算连续覆盖区间。
4. 仅对 `T_p'` 之后未被规范时间窗覆盖的时间区间生成补转写任务，并提升这些任务的调度优先级。
5. 丢弃携带代次标识小于 `g` 的迟到结果，避免旧播放区间的结果污染新区间。

与仅做字幕时间偏移校正的方案不同，本步骤的直接目的是确定「哪些区间已经转写过、无需再次推理」，其技术效果是减少重复推理与内存反复分配。

#### 4.5.5 实施例

**实施例 1：可预取音源（本地或已缓存的点播媒体）**

系统从应用媒体流直接抽取音频基本流并解码为脉冲编码调制数据，A=1，L 为媒体总时长减去当前播放位置，P 高于 P_th。此时选择预取轨：以 W=30 s 划分规范时间窗，按与当前播放位置的距离升序生成任务，抽取时额外读取前后各 2 s 邻域音频作为解码上下文，但输出只写入规范窗口。第一遍以基础解码配置得到粗转写文本，抽取其中的命名实体与领域术语构成偏置词表，再以携带该偏置词表的配置二次转写。随着 Δ 增大到 Δ_max 以上，闭环下调 B 并释放已完成窗口的音频缓冲。播放到达某一时刻时，其字幕条目早已处于已稳定状态，渲染器按绝对源时间戳直接读取，不需要等待任何推理请求。

**实施例 2：不可预取音源（直播、实时会议、语音通话）**

系统只能经操作系统级音频回环获得已经播放出来的音频，A=0，L=0，P 低于 P_th。此时选择流式轨，把 Δ_min 设为该流式模型的稳态延迟值，不启动非流式模型、不保留长前瞻缓冲。字幕条目初始状态为易变，经局部一致性判定后转为已稳定；对已稳定条目不再回溯修订，大差异以追加修正条目的方式呈现。该路径下系统不产生为不可预取音源预留的无效前瞻等待与缓冲占用。

**实施例 3：音源热切换与播放跳变**

用户在点播视频播放到第 3 分钟时跳转到第 48 分钟，随后又切换到一场直播，再切回该点播视频。第一次跳转触发 4.5.4 的重锚流程：已完成窗口保留，第 48 分钟所在窗口被提升优先级并补转写，旧代次的迟到结果被丢弃。切换到直播时 pid 变化，重新计算得到 A=0，工作轨由预取轨热切换为流式轨，切换边界取切换时刻之后第一个已稳定条目的起始绝对源时间戳，之前的已输出条目不回退修改。切回点播时以媒体指纹与管线配置键核对缓存键，键完全匹配则直接恢复该媒体的规范时间窗，不重新推理。

上述三个实施例共用同一条绝对源时间轴与同一个闭环调度器，不需要为每类音源配置独立的处理管线。

#### 4.5.6 多轨输出仲裁

在同一绝对源时间戳区间上，按「来源等级 + 词级后验概率 + 与相邻条目的时间连续性」计算各候选条目的置信度，选取置信度最高且状态为已稳定的条目输出。来源等级取值为平台字幕轨 > 预取轨 > 流式轨。轨间切换只允许发生在已稳定条目的边界处，切换点之前的已输出条目不作回退修改，从而避免时间轴回退与重复渲染。用户纠错产生的已修正条目写入个人词典，作为后续转写的解码偏置，并按媒体指纹缓存。

**图 3 · 闭环调度流程**

```
开始 → 取得 D 与合并视图 → 计算 P、T_t、Δ
     → P ≥ P_th ? ── 是 → 工作轨 = 预取轨；Δ_min = 预设下限
                 └─ 否 → 工作轨 = 流式轨；Δ_min = 流式稳态延迟
     → Δ < Δ_min ? ─ 是 → 增大 B（受 L 与内存约束）
       Δ > Δ_max ? ─ 是 → 减小 B，释放音频缓冲
       否则         ───→ 保持 B（滞回）
     → U > U_th ? ─ 是 → 下调 B / 暂停预取写入
     → 按窗口距离排序生成任务 → 写回统一时间轴 → 下一周期
```

**图 4 · 跳变重锚与增量补转写**

```
检测到 pid 变化 或 |ΔT_p| 超阈值

   → 提取当前音频指纹

   → 丢弃代次 < g 的迟到结果 → 输出仲裁
```
