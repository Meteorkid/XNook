# 第三轮：是否存在能带来更好效果的新方法

> 2026-11-13。本文回答「有没有可能创造一个新的方法，达到更好的效果」
> 配套：`LIVE-CAPTION-OPTIMAL-PIPELINE.md`（第二轮查证）· `LIVE-CAPTION-LLM-SELECTION.md`（选型）· `PATENT-PRIOR-ART-MATRIX.md`（对比矩阵）· `PATENT-DRAFT-系统级字幕调度.md`（申请草稿）

## 一、结论先行

这是第三轮独立检索：6 组查询、8 个候选方向，**全部命中已公开文献**，其中多数是 2025–2026 年发表或公开的。加上前两轮，累计约 20 个候选方向无一幸存。因此：

- **专利/单点层面：没有真空。** 继续追问「有没有新算法」的边际收益已经是负的。这个领域的公开速度明显快于单点构思的产生速度，且很多构思可追溯到 2003–2014 年。
- **效果层面：有，但不是新方法，是换目标函数。** 本轮第一次找到「为什么所有方案看起来都到顶了」的原因：现有方案（包括本项目自己的草稿）都在优化 **CER / 延迟 / 算力**，而真实痛点是**少数高后果错误**。这两者在本轮数据中明确脱钩。
- **但这个方向也不能当发明点**：连「按语义重要性动态分配算力」这个动作，都已被 2012 年的公开申请写明。它只能作为工程路线与评测口径，不能写进权利要求。

一句话：**这不是「找到新算法」的一轮，是「发现优化目标选错了」的一轮。**

### 1.1 关键反差

同一段 60 秒中文素材、同一台机器（公开实测笔记，非同行评议）：

| 引擎 | 整体字错误率 | 专名正确 |
| --- | --- | --- |
| Whisper large-v3-turbo | 8.5% | **2/11** |
| 中文优化引擎（约 800M） | 8.6% | **10/11** |

整体 CER 相差 0.1 个百分点，专名正确率相差 5 倍。**按 CER 排序的选型、按 CER 收敛的评测集、按 CER 做门控的纠错层，都会系统性地看不见这批错误。** 而「姚顺雨→尧舜禹」「肇庆→赵庆」这类错误恰好是：错字仍是合法中文词、置信度还偏高、且会一路进入正文与检索索引。

这解释了一个此前反复出现却没被归因的现象：置信度门控失效、LLM 纠错净收益为负、跨模型分歧也只能覆盖部分错误——它们的共同缺陷不是算法不够好，而是**都在用模型自评信号找错误**，缺少一个独立于模型、按后果严重性定义的信号。

## 四、效果层面真正能更好的路线：换目标函数

### 4.1 从「把每个字识别好」改成「保证高后果位不出错」

现有闭环（本项目草稿亦如此）的控制量是「转写前沿 − 播放前沿」Δ、「推理单元负载 U」、「字幕覆盖率」。它们都在回答**「算完了没有、算力够不够」**，不回答**「算得对不对、错在哪里代价最大」**。

建议保留这些量做资源调度，另加一个独立的**质量状态量**：

```text
高后果位 HighConsequenceSlot {
  slot_id
  source_timestamp_range
  category        // 人名 | 地名 | 机构/品牌 | 术语 | 数值/金额/日期 | 否定与程度词
  surface         // 当前采纳的规范形，未定时为空
  pinyin_syllables[]
  status          // unresolved | provisional | confirmed
  evidence[]      // 来源等级：user | metadata | platform_caption | multi_engine | full_video
  consequence     // 该位出错对检索/理解的后果权重
}
```

闭环控制量改为：**未定高后果位占比** `R = 未确认 slot 的加权数 / 已探明 slot 的加权数`，并据此决定三件事——是否追加定向识别、切哪个引擎、是否允许该区间字幕进入 `Stable` 状态。

关键区别：`R` 是**后果驱动**的，不看模型自评置信度；`Δ` 是**进度驱动**的。两者正交，可并存。

### 4.2 为什么这会带来真实收益

1. **算力重分配**：把有限预算从「均匀降低整段 CER」转到「消灭少量高后果位错误」。1.1 的数据说明这两件事在同等算力下结果可以差 5 倍。
2. **绕开失效信号**：不需要置信度、不需要 LLM 自由改写、不依赖跨引擎一致性，因此不受「高置信度错」「共享错误」「过度改写」三类已知缺陷影响。
3. **与上一轮选型完全一致**：LLM 仍只做识别前的候选锚点生成与全片归纳（输出可丢弃、不碰正文）；同音字仍走拼音约束的封闭候选替换；`US12154558` 那类音素 rerank 正好可复用。
4. **可预取音源红利升级**：全片先建锚点表 → 播放时任何与该表冲突的实时轨输出按锚点替换。这是「提前识别」从「提前算完字幕」升级为「提前建立事实」，比窗口缓存复用更进一层。

### 4.3 不能做的事（重申）

- 不把 `R` 或「按语义重要性分配算力」写进权利要求：2.3 已列明在先公开；
- 不用 `R` 替代 `Δ` 作为草稿独权控制量：草稿的创造性论证建立在「应用无关 + 可预取性 + 双前沿差」上，换控制量会推翻已有论证；
- 不把「用户看得更准」当技术效果写进说明书（中国 AI 算法类客体要求落在系统内部性能）；
- 不在没有分层评测集的情况下宣称收益。

**`R` 的定位是工程内部质量状态量与评测口径，不是发明点。**

## 五、两个可立即复用的现成加速机制（工程手段，非发明点）

虽然单点不新，但本轮查到两条能直接提升本项目「更高效」的现成路径：

1. **可预取轨用 draft-verify 压缩预转写时间**。SpecASR 在 LibriSpeech 上以小模型出草稿、大模型一次批量验证，达 3.04–3.79× 无损加速（WER 不降），其「audio as anchor」洞察是大小模型受同一声学信号约束、输出天然对齐；自适应阈值减少 74.1% 无效预测步。若能迁移到 `large-v3-turbo` 预转写，Δ 会更快领先播放前沿，更多区间落到零感知显示。
2. **不可预取轨类推「空闲算力预起草稿」**。Speculative Listening 证明了在输入到达前利用空闲窗口预计算、音频到达后一次验证是可行的，且训练无关。

但两条都有必须核实的迁移风险：

- SpecASR 的实验是**英文 LibriSpeech + TinyLlama 草稿 + Llama-7B/Vicuna-13B 目标**，不是中文、不是 Whisper 系；
- `mlx-qwen3-asr` 的实验性投机解码实现已验证 greedy parity，但**在短片段与 10 秒音频上没有速度提升，原因是草稿编码器开销**——这恰好是本机最可能遇到的情况；
- Speculative Listening 面向全双工语音对话（假设下一块是静音），字幕场景的「静音假设」不成立，需要换成「上下文 + 实体表条件下的语言先验草稿」，且 Alignment Drift 论文已指出草稿必须跟踪音频位置，否则接受率会崩。

因此两条列入「待实测」，不写进当前推荐架构。

## 六、验证方案：评测集必须分层

沿用 `LIVE-CAPTION-LLM-SELECTION.md` 第八节的 20–30 段中文视频评测集，但指标必须**至少分五层**，否则看不到第四节的收益：

| 指标 | 为什么必须单列 |
| --- | --- |
| 整体 CER |  conventional 基线，但不足以区分引擎（8.5% vs 8.6%） |
| **高后果位错误率**（按 4.1 的 category 分层报） | 本轮的核心发现，是真正要优化的量 |
| 零推理区间占比 | L0 覆盖图的提效收益 |
| 端到端呈现延迟（`--comp_unaware` 测下界 + 真实链路） | 防止以延迟换准确率 |
| 变差句数 / 净 CER 变化 | 任何纠错层的准入条件 |

先做一次**引擎对照实验**：同一批素材分别跑 Whisper large-v3-turbo 与中文优化引擎，只报高后果位错误率，确认 1.1 的反差在自己数据上是否成立。若不成立，第四节整条路线就不值得投入——这是最便宜的证伪方式。

## 八、结论

**问「能不能创造新方法达到更好效果」，答案要拆成两半：**

- 作为**可申请专利的新方法**：不能。三轮累计约 20 个候选全部被在先公开覆盖，本轮新增的 12 件对比文件进一步压缩了空间。草稿的收窄方向（应用无关 + 可预取性 + 双前沿差 + 多轨仲裁）仍是目前最站得住的组合，不应推倒重来。
- 作为**工程效果**：能。路径不是新算法，而是把优化目标从 CER 换成高后果位错误率，并用「未定高后果位占比」做质量闭环。这条路线不产生新专利，但可能比继续找单点算法更有效地改善用户实际看到的字幕。

**建议停止继续追问单点创新**，把资源转到两件可证伪的事上：分层评测集，以及 4.1 的引擎对照实验。
